# Monitor机制讨论稿：证据角色、陈述对齐与可执行干预

日期：2026-10-08。状态：**研究者要求的机制设计讨论；未批准为研究方案，未实现、推理或训练。** 现行[主方案](Actor_Monitor_MVP_Protocol.md)、冻结Actor策略、原审计标签及74个Monitor预留来源组不变。

## 1. 结论与研究边界

建议将“证据角色约束的对照核验Monitor”作为待讨论的主候选：从实际工具日志建立带类型、来源、时间和范围的证据记录，对照Actor已有结构化陈述；争议时选择一个与疑点相关的输入变化，检查Monitor是否保持应有的不变性或作出应有的变化；拒绝STOP时必须给出可执行的重要缺口。

这里的“对照”检查Monitor如何使用输入，不证明Actor内部思维的因果忠实性。Monitor不预测新的real/fake标签，不从工具原始score构造未经验证的概率，不把多个同向信号当成统计独立。

工程上可先复用现有输入适配、Actor字段、引用解析和冻结工具。语义效果、独立标注一致性以及在线收益均未验证，不能给出实现成功百分比。最难的部分是开放式证据充分性及冲突权重，而非JSON解析。

## 2. 本地实现核对

核对文件：

- `experiments/actor_b/actor_b_protocol.py`：Actor已经输出`current_evidence`（source、observation、interpretation、direction）、`unresolved_conflicts`、`evidence_gap`、`next_action`、`selected_tool`、`action_reason`、`final_verdict`、`final_confidence`。验证器只审结构；可直接观察归因、综合、冲突与停止问题，无需先修改Actor字段。
- `experiments/actor_b/actor_b0_d/run_b0_d_condition.py`：一个step先生成Actor请求，随后才附本次工具返回。**该step的Actor文本不能使用其后才返回的observation**；下一次Actor决策才可用。格式重试不计调用额度，通过解析并进入调用流程的请求计入；首步PROBE-DELAY阻断也计入；成功工具不能重复。
- `experiments/faithbench_monitor_v0/monitor_protocol.py`：已有call_prefix/terminal适配、JSON Pointer引用、原文匹配、中文说明与状态一致性校验；没有模型推理和语义有效性判定。`render_request`是文字输入，crop文件名不提供像素。
- CALL前缀包含预算和exposed_tools；terminal分支没有显式顶层budget/exposed_tools。未来审核STOP应从日志与冻结规则重建运行状态，作为显式快照提供。不可只数成功返回或由Actor自述推算。当前工具卡和rules已经存在，不是重新发明工具接口。
- 现有七类标注规范及Schema仍是开发草案，不能把本文动作建议或标签含义自动写回。

本轮不重新打包907输入，不读取私有逐样本标签、身份映射或预留组，不重跑已有测试。

## 3. Monitor与Actor分别看什么

令决策时刻为t：

- E_t：截至t已经实际返回的工具证据；
- A_t：当时的Actor请求与陈述；
- H_t：此前动作、工具返回、执行状态、结构重试；
- R_t：工具说明、执行约束、可用工具、计费CALL历史与剩余额度。

在线Monitor只读取这些当时信息。离线可以拥有完整存档，但每步判断仍须按可见时间裁剪；不能用后来的返回为前面的陈述追认支持。完整终态审核与逐CALL前缀审核分别保留。

| 信息 | Actor现状 | 候选Monitor使用方式 |
|---|---|---|
| 原图 | Actor可看 | 文字主候选先不看；多模态扩展看同一原图 |
| 已返回Evidence Cards | 可看 | 直接读原始返回，不以Actor摘要替代 |
| PROBE crops | PROBE返回后可看 | 文字候选不含像素；扩展仅用当时已经返回的同一批crops |
| 工具说明与局限 | 已提供 | 转成明确、可定位的角色约束；语义来自同一冻结工具卡 |
| Actor结构化陈述与动作 | 自己生成 | 作为待核对主张，不当成真实证据 |
| 执行记录与预算 | 收到规则/反馈 | 由runner记录重建，不相信Actor声称的预算或成功状态 |
| 真假GT、来源组、未来结果、silver标签 | 不是在线决策证据 | 不进入Monitor输入 |
| 额外专家模型返回 | 现行无新增 | 第一版不增加；若以后加入，必须作为额外信息条件单列 |

输入不同主要是组织方式、审核对象和操作日志；不需要偷偷提供额外真假线索。文字与多模态输入差异要单独报告。更换Monitor模型也是单独变量。同一模型的独立调用只是上下文隔离，不保证错误独立，更不能成为金标签。

## 4. 核心机制：监测的不是七个词，而是具体证据关系

### 4.1 原始证据记录

对每次成功返回创建Monitor内部记录：

`evidence_id, source_ref, available_at, evidence_type, scope, observed_signal, allowed_uses, limitations, execution_status`。

这些是新候选的内部字段，不修改Actor或当前Schema。信号与执行状态尽可能由代码读取；allowed_uses先依据研究者确认的冻结工具语义手工登记，不能让LLM在每图临时发明许可。自由文本适用性仍需语义核验。

角色示例：PROBE是参考分布偏离/定位；local是可误报的局部方向信号且禁止单独支撑最终结论；complementary是有分布局限的补充方向意见；provenance缺失是inconclusive，未经验证声明不是来源证明。标准化real_like/synthetic_like用于工具意见对齐时要保留原枚举，不能改称图像真实来源。

记录先从日志建立，再读Actor综合。每一处证据重复出现仍对应同一个evidence_id，不因Actor反复复述而增加支持数量。不同工具来源不意味着错误统计独立。

### 4.2 陈述对齐

优先使用Actor已有的source、observation、interpretation和direction，减少对长文重新抽取。一个字段含多个命题时再分解；保留否定、条件、假设和强度限定。检查action_reason、evidence_gap与最终解释，避免只看结构化direction而遗漏隐含归因。

| 核验关系 | 可观察对象 | 代码可确定的部分 | 仍需要语义审核的部分 |
|---|---|---|---|
| 来源存在 | 陈述source、原工具日志 | 是否调用成功、引用是否存在 | 陈述究竟归因给谁 |
| 时点合法 | Actor生成时刻、返回时刻 | 是否在该决策前已可见 | 是否只是明确的未来假设 |
| 数值/信号保持 | 原始signal/score与observation | 枚举与可直接对齐的数值 | 转述是否改变含义 |
| 类型许可 | 偏离、方向、来源声明等角色 | 已确认的禁止转换 | 隐含真假支持、合理推断边界 |
| 范围保持 | 图块、区域、整图、来源链 | 已有范围元数据 | 是否夸大为整图/来源证明 |
| 冲突覆盖 | 相关方向信号、Actor冲突字段 | 已知可比较信号是否相反 | 是否已承认、是否有依据地处理 |
| 支持覆盖 | 最终主张的证据集合 | 引用覆盖、重复来源去重 | 多证据综合是否满足已确认口径 |

原始signal为real并不逻辑蕴含“图像为真实摄影”。单条转述正确与最终真假结论充分分别判断。引用存在也不等于引用蕴含该陈述。

### 4.3 角色越界与沿轨迹传播

示意：PROBE百分位→“假图概率”→“全局工具支持fake”→“多个工具一致”→STOP。这条链含数值语义改变、方向赋予和综合夸大。Monitor分别定位原始返回、首次越界陈述和后续使用该陈述的步骤，而不是把所有问题压成一条最终FAIL。

发现上游错误后，不自动把后续所有步骤判错；只核对实际依赖该错误的陈述。关系记录用于来源与主张的依赖定位，不能被宣称为已经证实的内部因果图。

## 5. STOP怎样形成可审计判断

仍待研究者确认的候选控制层：

1. **允许证据支持的STOP**：关键陈述有合法支持；与结论有关的重要冲突有依据地处理；符合已确认的充分性规范；没有需要继续获取的重要证据。此处的“支持”是按规范的支持，不是保证真假正确。
2. **要求修正解释**：主要问题是误述、归因、过强措辞或遗漏已有证据；现有证据足以完成修正。不能把每个解释错误转成一次新工具调用。
3. **要求补证据**：存在重要缺口，且当前有合法、与缺口相关的补证据途径。
4. **受限结束**：预算已耗尽，或确实没有可执行的相关途径；另行记录结论是否受支持。不能把所有工具未调用完当成一定还能补到所需证据。
5. **无法裁决**：缺少像素、适用性、校准或可信来源信息，无法合理作充分性/冲突权重判断。Monitor不得自行猜出证据权重。

拒绝STOP需给出“继续依据”：

`具体缺口 + 原始证据引用 + 影响哪个主张 + 缺少哪类证据 + 工具能力依据 + 当前预算/可用性`。

工具可调用只证明操作可行，不证明它一定返回有用证据或足以解决冲突。该依据是事前可说明的相关性，不是未来收益预测。对Actor输出证据需求即可；内部可以登记可行工具以核对可执行性，不替Actor发出具体调用命令。

**核心未解决问题**：没有校准似然、已确认的误差依赖和独立充分性标签时，不能推导“两个工具一致就足够”或“某分数超过阈值就足够”。建议第一版确认可引用的必要条件、硬性禁止项和有限的允许情形，把剩余争议标为unassessable。若允许情形无法经独立标注稳定确认，第一版研究目标应先限定为证据误用及可执行提前STOP检测，不能宣称解决了普遍证据充分性。

当前`stop_justified`是否包括受限结束尚未确认；本文不重新解释历史silver字段，不改原标签。现有FAIL/PASS/UNASSESSABLE是审核结论，与未来控制层动作不是同一对象。

## 6. 主候选的研究增强：证据角色对照核验

一个普通Judge可能根据工具名、Actor口吻或终态方向给出看似合理评价。候选方法检查：当某类输入改变时，**哪项核验应改变，哪项应保持**。约束只作用于指定局部关系，不要求所有总体判断不变。

| 输入变化（未来经确认后才构造） | 应有关系 | 必须保留的边界 |
|---|---|---|
| 工具标签一致改名，说明、轨迹和引用同步 | 对齐名称后，证据角色和违规判断不变 | 不遗漏引用变更，不额外给某方法的隐含信誉 |
| 改变合法的PROBE偏离值，相关观察转述同步 | PROBE仍没有真假方向；不能成为假图概率 | 补证据优先级可以变化；不能要求所有STOP判断不变 |
| 原方向signal翻转，score等关联字段同步；Actor旧方向主张保留 | 该主张对该工具返回的匹配/支持状态必须变化 | 不要求总体verdict必然翻转；其他证据仍可支持它 |
| 删除一份被引用的证据，保留被审主张 | 对应引用/依赖不能仍获支持 | 去掉冗余证据不一定改变总体结论 |
| 同一证据状态下改为合法、可重建的预算耗尽状态 | 证据支持不因预算自动变强；补证据动作必须尊重额度 | CALL历史和运行状态须同步，不能制造自相矛盾的预算包 |
| 保持命题含义，仅改变等义表达 | 陈述关系判断应稳定 | 若改变了断言强度，就不是语义等价的负对照 |

这些变化作用于Monitor输入副本，不改原轨迹，不改冻结工具，不运行Actor反事实续跑，也不生成假图。角色关系来自工具语义或受控变化，不代表自然数据的全部金标签。每对的预期关系与合法性需独立审核，拒绝把模型自动变换的结果直接当真值。

在线候选可只在来源/方向冲突或无法裁决的个案上增加一次相关核验。若原审核平均一次模型调用、触发比例为q、每次触发一次额外调用，则名义模型调用数为1+q；这不是GPU用时或金钱估计，token和延迟还需实测。只有重建预算、字段/引文匹配等CPU工作不需要GPU。

**对照不一致本身不是原轨迹违规证据**。可能是输入变化非法、预期关系不适用、提取失败或Monitor不稳定。若不能回到原输入定位具体违规，应转人工复核或unassessable，不能直接FAIL。对照模块也可能没有提供超越确定性规则的收益，这是明确的否证结果。

## 7. 两个输入变体及替代方案

### 7.1 先证据、后陈述的隔离视图

第一轮模型只读取当时原始证据和工具语义，列出方向信号、局限和冲突，不读取Actor最终verdict/自信措辞；第二轮再核对Actor陈述。两轮必须使用隔离上下文；只在同一prompt里要求“先看证据”不能证明避免了锚定。

优点：可检验Actor叙述是否把Monitor带偏。代价：增加调用，第一轮也可能解释错。MVP可以先用确定性记录+一次语义核验；隔离视图作为消融，而非默认堆两个模型。必须与同样两轮调用或相近token预算的普通Judge比较。

### 7.2 按主张触发视觉核验

只有当被审主张涉及可见像素（如“某crop中边缘断裂”）时，提供同一原图和当时已返回、与主张有关的crop。Monitor输出可见、矛盾或无法确认，附已有region_id/bbox及限制。

从“边缘断裂可见”跳到“图像AI生成”仍需合法来源支持；视觉一致性不是深伪检测证明。PROBE异常crop不是语义伪造区域，也不保证覆盖Actor说的部位。若现有资产未覆盖，应unassessable；第一版不新增裁剪/像素工具以免改变研究条件。

多模态条件要与使用同样像素、同样模型的普通Judge比较；不能将更多信息的收益归为监测算法收益。该变体能扩大可审核主张范围，但不一定是主创新。

### 7.3 不建议作为当前主线的方案

- 直接增加更强的真假专家给Monitor：更像新增分类/融合能力，需独立处理额外信息效应。
- 完整专家可靠性学习与加权融合：需要额外校准数据，与AgentFoX已有路线接近，会扩大MVP。
- 用Actor真实反事实重跑证明内部证据依赖：更接近因果归因研究，增加GPU开销并需新实验协议；不是本文轻量输入对照所能证明的事。
- 先训练复杂图神经网络或Monitor SFT：当前独立标签未准备好，无法证明必要性。

## 8. 具体示意：一个可检验的审核对象

以下完全是文字示意，不是现有样本，不是开发标签。

可见证据：e1=PROBE高偏离且不返回真假方向；e2=local synthetic_like；e3=complementary real；本次STOP前剩余1次CALL，provenance尚可用。

Actor写：“PROBE和局部工具都支持fake；互补工具只是弱意见；多数证据一致，可以停止。”

Monitor先由日志得到：e1无真假方向，e2/e3具有相关相反意见，尚无可比较的工具可靠性权重。然后对齐主张：

- “PROBE支持fake”违反非方向证据边界；定位e1限制与Actor该句。
- “多数证据一致”将e1算作真假票，并忽略e2/e3的相反意见。
- “互补只是弱意见”若没有适用性/校准依据，不能用于证明冲突已解决；保留具体争议而不自行判谁正确。
- 是否继续：provenance能提供来源线索，但可能返回inconclusive。只有能说明来源线索与当前关键缺口相关、并确认执行条件时，才可提出该类补证据请求，不能保证它解决冲突。

若预算改为合法耗尽状态：前面归因和综合问题仍在；可结束调用，但不能把fake结论变成受支持。若现有证据经修正已经满足获批口径：要求重写解释即可，不需要强制新增调用。若三个工具意见都不够提供权重依据：Monitor可以确认归因错误，同时对充分性保留unassessable。

## 9. 可证伪假设与公平评价（均为待确认建议）

| 候选机制假设 | 竞争解释 | 能区分两者的评价 |
|---|---|---|
| 来源/角色/时间对齐能减少隐含归因与错误综合 | 只是在修补容易的枚举错误 | 规则层单独基线；显式字段错与自由文本隐含错分层报告；人工确认定位 |
| 角色对照帮助模型发现错误依赖 | 仅仅多调用一次，或产生更多拒绝 | 同模型/同输入/相近预算普通Judge；两轮Judge对照；报告误拒与unassessable覆盖 |
| 可执行缺口约束减少错误继续/预算耗尽循环 | Monitor只是更保守或更少干预 | 同时报告提前STOP检出、合法STOP误拒、无依据补证据和修正解释/补证据区分 |
| 隔离证据视图降低叙述锚定 | 摘要损失信息或第一轮模型错误 | 保持原证据相同，比较有无隔离；检查同义表达和自信措辞对局部关系的影响 |
| 视觉变体核验具体视觉主张 | 仅是新增像素提高总体判断 | 同信息多模态Judge；视觉主张单独评价，不由真假accuracy替代 |

基线建议：规则层；普通全轨迹Judge；加入相同工具规范的Judge；加入证据记录/对齐的候选；再加对照核验。只挑与主假设有关的消融，不一次实施全部变体。所有模型/输入/调用次数/解析重试规则均需记录。

评价对象：有引用的错误定位、隐含归因、相关冲突覆盖、STOP误允许与误拒、继续请求可执行性、证据不足与无法判断的区分；同时报告coverage与错误率，防止全拒绝或全unassessable取得表面好成绩。在线效果需真正按冻结前缀接入后再研究，离线审核不能证明在线收益。
