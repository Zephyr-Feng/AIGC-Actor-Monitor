## 1. 研究目标与当前定位

Actor负责读取图像、调用取证工具、解释证据并形成判断；Monitor审核Actor是否忠实使用证据，指出具体问题；反馈接口决定哪些修改可以执行、哪些应保留未决。

当前核心目标是同时做到四件事：正确反馈能促成实际纠错，错误反馈不引发误改，资料不足时保持未决，有据内容得到保护。近期实验固定Actor权重，只对Monitor做了小规模本地适配。

项目重点在证据解释与反馈机制。现有证据尚不足以声称提高了图像真假检测准确率，也不足以声称解决了所有取证停止决策。

## 2. 已形成的系统与接口

工具通过证据卡提供原始观测、来源、范围、方向和局限。特别区分“异常观测”“解释”和“真假结论”：全局表征偏离本身不直接证明图像由AI生成。

当前保留的闭环为：

1. Monitor根据原始证据和待核回答提出反馈。
2. 程序检查原文定位、来源及允许修改范围；明确未决直接分流。
3. 固定Actor提出局部修改候选。
4. 选择阶段依据原始证据比较原文和候选，隐藏原文身份，并检查交换顺序后是否一致。
5. 满足执行约束才应用局部修改，否则保持未决。

程序还保护终态、置信度、动作和证据卡等不可改内容，阻止整段旧字段误插入局部位置。顺序一致只能检查位置敏感性，引用存在只能检查来源标识；二者都不能证明内容正确。同一个Actor重复选择也不是多个独立裁判。

这套组合来自仓库既有协议、通用局部修订与来源约束思路，以及实际失败案例的迭代。不能据此宣称全新原创算法，或声称已有论文直接验证了当前完整组合。

## 3. 研究推进与主要结果

| 阶段 | 已得到的认识 | 当前决定 |
|---|---|---|
| 早期Monitor与提示、引用契约开发 | 能改善格式和部分问题定位，仍有证据误读、方向混淆和漏检 | 保留有用组件，不以接口通过代替语义通过 |
| 公开材料反馈训练及混合训练 | 受控短题较易改善，自然全文安全纠错仍不足；更长训练出现正确内容被误改 | 历史00952、00453候选未晋级 |
| 多轮反馈接口与删减对照 | 具体正确反馈有局部帮助，错误反馈也会锚定Actor；增加步骤不能创造正确候选 | 保留最小执行保护，停止默认叠加自审与复杂证明 |
| 2026-10-21 Monitor定向训练 | 未提供的数量更能保持未决，有限正确主张未退步 | 保留checkpoint-00012为研究候选 |
| 冻结后的有限新来源检查 | 新数字和措辞下仍能区分已知检查数与未知库容量 | 支持局部能力，不作为整体可靠性认证 |

历史训练也留下了重要反例：2026-10-17一轮训练后，80项严格JSON由47项增至80项，但自然全文仍没有一条纠错反馈满足当时完整联合要求；2026-10-19混合训练中，7条无错控制全部被提出修改，新候选未晋级。上述检查范围和模型条件不同，不能跨轮相加计算准确率。

## 4. Monitor犯错时，Actor目前如何反应

目前的实例支持“有条件抵抗”，尚不支持“普遍可靠拒绝”。

| 情况 | 实际观察 | 证据边界 |
|---|---|---|
| 正确反馈 | 对明示注入的“表征偏离已证明AI生成”，Actor撤回证明说法，保留偏离观测及工具局限 | 局部注入控制，不代表自然整稿全部修好 |
| 错误反馈 | 助手构造按0.5阈值要求翻转结论的建议；Actor新文仍依据实际校准阈值保住真实方向 | Actor做了改写，不能称原样拒绝；仅一个受控来源 |
| 资料不足 | 新Monitor将未知库容量标为未决，接口没有调用Actor或生成补丁 | 是Monitor与程序分流，不是Actor主动弃答能力 |
| 内容保护 | 本轮三份Actor结果的证据卡、允许范围和非解释字段内容检查通过 | 证明操作边界，不能替代文字语义与真实性审核 |

此前也存在错误Monitor建议把Actor带向错误解释的案例；后续选择阶段有时能挡住，但正确候选根本没有生成时，选择器也无法补救。因此需分别评价反馈内容、Actor修订和补丁执行，不能只看接受率。

## 5. 失败经验与仍未解决的问题

首先，格式、引用和标签进步不等于会审证据。模型可能引用真实存在的卡片，却把无方向观测说成真假支持；也可能理由认出问题，建议却反向修改。

其次，未知应与明确错误区分。新候选在参考库容量上有所改善，但过去未知选择实验曾反复选择第一个候选，不能将程序保守回退说成模型已经学会弃答。

第三，不能把复杂提示或更多调用当作默认解决办法。事实账本没有带来净改善；最近只审问题段、再拆分历史状态与当前修订权限的两批共6次生成均未实现预期变化，已停止同源换词。

第四，评判依据本身也要复盘。012历史轨迹直接记录用了3次工具，但未直接给出完整可用工具清单；历史预算和当前修订零调用权限又曾混放。因此此前“无更多工具”必然错误的助手判断不能充当已核证gold。保留原结果和分数，记录判据待澄清，不事后把未达目标改称成功。

当前主要缺口是：自然长回答中的多问题覆盖、正确与错误混合时的安全修订、证据所属时点和工具可用性绑定，以及更充分的独立端到端验证。现有开发审阅不属于独立人审gold。

1. 先用已有输出梳理自然整稿的漏检、误报和修订残留，明确每个判断的时点、可用性和证据，避免重复调用。
