## 02 一句话总结

[Paper] EviGraph 不额外训练任务策略，而是以全局层、区域节点和区域关系组织现成取证工具的输出，统一完成整图生成判断、局部篡改定位与类型报告；在作者构建的组合伪造基准上，完整系统的 Composite Accuracy 为 0.402，但这不等于报告内容已经过独立忠实性验证。[Paper: Section 3; Table 3]

## 03 研究问题

[Paper] 同一幅图可能同时经历整图生成、换脸、文本修改、拼接和物体移除。传统专用检测器各有覆盖范围，直接把多个检测器的分数拼进提示词，又容易丢失“哪条证据属于哪个区域”的对应关系。[Paper: Section 1 Introduction; Section 3.1 Overview]

精确问题是：**能否在不为该任务额外训练 agent 的条件下，让一个系统在组合伪造图中同时回答“整体是否生成、哪里被改、属于什么操作”，并把每项结论追溯到对应区域与工具？**

[Analysis] 这里包含两个不同目标：任务覆盖与结果可追溯。前者可由分类、定位和联合正确率检验；后者还需要逐主张的证据核验，不能只用同一组任务指标替代。

## 06 核心思想

**表层实现。** [Paper] 给每个可疑区域建立地址明确的节点，把工具的状态、离散判断、原始分数和资产引用写入该节点；再沿区域关系检查一致性。[Paper: Section 3.2 Evidence Graph]

**核心洞见。** [Paper] 取证证据必须带着归属参与推理：分数不仅是“异常 0.8”，还应说明是哪个区域、哪种检测维度、由哪个工具得到。证据图是共享状态；它不是额外训练的图神经网络。[Paper: Sections 3.2–3.3; Figure 2]

**可迁移原则。** [Analysis] 可以借鉴的是“保留证据来源、作用范围、未知状态与原始结果”。是否一定需要图结构，仍须与保存同等信息的结构化表格对照；现有消融不能排除收益主要来自字段绑定。

## 07 方法总览

```text
输入图像
  → VLM 场景理解 + SPAI/AIDE 整图检测 + EXIF 侧信息
  → 形成全局判断及下游指引 τ
  → VLM 提议语义区域；TruFor/DTD 提议信号异常区域
  → Florence-2 定位、VLM 复查；按类型与重叠合并候选
  → 建立区域节点与空间/物理关系
  → agent 选择检测维度；规则 H 过滤不适用调用
  → 工具执行、Qd 离散化、关系一致性检查
  → 对区域判定与操作分类
  → 输出掩膜及可追溯报告
```

[Paper: Figure 2; Algorithm 1; Sections 3.3–3.4]

输入不要求给定真实篡改区域；候选来自模型与检测器。工具使用现成权重，不做本文任务微调。全局判断中的 EXIF 不参与投票，只作条件性侧证；正文没有充分展开双通道投票分歧时的具体处理规则。[Paper: Section 3.3 Stage 1; Section 4.1]

[Analysis] 这是分阶段的工具编排流程。算法中没有独立 Monitor 反复审查报告、让 Actor 修订并验收的闭环，也没有单独检验 STOP 决策。文中“single pass”不能理解成一次模型调用或没有多次工具执行。

## 09 关键公式与符号

**图结构：** \(G(I)=\langle g,V,E\rangle\)。\(g\) 是整图状态，\(V\) 是区域节点，\(E\) 是区域关系。目的在于让证据可定位、关系可检查。[Paper: Section 3.2]

**Equation 1，证据条目：**

\[
\varepsilon=\langle\sigma,\nu,s,\rho\rangle.
\]

\(\sigma\in\{unknown,tested\}\) 表示是否执行；\(\nu\in\{clean,anomalous,inconclusive\}\) 是离散结果；\(s\) 保留原始工具分数；\(\rho\) 指向掩膜或统计资产。[Paper: Equation 1]

**离散化：** \(\nu=Q_d(\phi_d(I,b))\)。\(\phi_d\) 是维度 \(d\) 的工具，\(b\) 是区域，\(Q_d\) 将原始输出映射成离散状态。直觉是给异质结果一个公共接口，同时保留原值；阈值声称预先固定，但 Appendix C 未提供。[Paper: Section 3.2 Evidence entries]

**Equation 2，全局层：**

\[
g=\langle desc,\varepsilon^{vlm},\varepsilon^{expert},\varepsilon^{exif},\pi\rangle,
\quad \pi=\langle\nu_{glob},\alpha,c,\tau\rangle.
\]

\(desc\) 为场景说明；\(\alpha\) 记通道是否一致，\(c\) 为置信度，\(\tau\) 为后续指引。不能把这里的 \(c\) 自动当作经校准的真实概率。[Paper: Equation 2; Section 3.3 Stage 1]

**Equation 3，区域节点：**

\[
v=\langle t,desc,b,\omega,(\kappa^{vlm},\kappa^{imdl}),S_v,\psi_v\rangle.
\]

\(t\) 是区域类型，\(\omega\) 记候选来源，\(\kappa\) 保留两路初始怀疑，\(S_v\) 存证据槽，\(\psi_v\) 为区域结论。输出类型 \(y\) 只有 `Modification` 与 `Removal`；不能把数据构建中的六种操作缩写当作模型直接预测的六分类标签。[Paper: Equation 3; Section 3.5]

## 11 如何正确理解结论

1. **train-free 指本文系统无额外任务训练。** 它依赖已训练的 Qwen3-VL 和多个专用专家，不意味着无需训练数据、校准或人工规则。[Paper: Section 4.1; Section 3.2]
2. **全局真实与局部篡改不是相反命题。** 全局层判断整体是否 AI 生成；非生成底图仍可有换脸、文档编辑或移除操作。直接映射为项目中的单一 `real/fake` 会改变标签语义。[Paper: Figure 1; Section 3.3 Stage 1]
3. **“细粒度类型”需要按实际输出读。** 主文区域类型为 Modification/Removal，并未展示对每种具体生成工具或编辑机制的精细归因准确率。[Paper: Equation 3; Table 3]
4. **可追溯不等于忠实。** 保存 node/tool/slot 地址改善了检查条件，但报告仍可能夸大分数、误读工具含义或忽略相反证据；没有相应独立量化指标。[Analysis; basis: Section 3.3 Stage 4; Tables 2–6]
5. **Comp. Acc 约 0.40 是能力边界。** 在该严格联合口径下仍有约六成图像未全部答对，但缺失匹配定义使失败构成无法完全分析。[Paper: Table 3; Section 4.1]

有边界的结论是：**作者结果支持“绑定区域的多工具证据状态有助于组合取证”，并未证明每条报告主张都可靠，也未证明独立监督和纠错已经解决。**

## 16 研究设想

以下为 **Agent-derived research candidates**，只供讨论，不构成新实验、数据分配或用卡授权。创新状态均为 **unverified**，需要专门查重。

### 候选一：先区分字段绑定收益与关系图收益

- **来源观察：** 无图设置同步移除了几种结构信息。[Paper: Table 6]
- **核心假设：** 保存区域 ID、工具来源和作用范围的表格，可能获得完整图的大部分收益；边检查再提供额外但较小的增益。
- **相对变化：** 改证据表示，保留工具、候选、原分数和 Actor。
- **初始方法：** 设计自由文本、绑定表格、无边节点、完整图四种等信息输入。
- **如何验证：** 在另行授权的同一来源分组评测集上配对比较，固定 token 与调用预算，测区域错引、无依据主张、结论正确及联合正确率；若绑定表格仍明显落后完整图，则否定“绑定已足够”的假设。
- **可能失败：** 表格与图难以严格等长；图的隐含提示更强；既有样本多为单区域，无法检出关系收益。
- **创新状态：** unverified；不把结构化绑定本身声称为创新。

### 候选二：对 τ 和候选归因作独立监督

- **来源观察：** 全局指引影响后续候选与证据计划，候选漏检仍明显。[Paper: Algorithm 1; Table 5]
- **核心假设：** Monitor 将“全局生成性”“局部篡改”“证据不足”分开核对，可降低早期错误被后续报告放大的概率。
- **相对变化：** 在固定 Actor 外增加语义审核，不新增检测器、不替换分类标签定义。
- **初始方法：** 先复用已有轨迹，检查每条主张能否绑定正确区域、工具字段和适用范围；输出最小修正及未解决项。
- **如何验证：** 经另行授权后，在同源配对轨迹上比较原输出、普通反馈、受控反馈；预先限定调用预算，报告错误修复、正确内容保留、误改与最终联合正确率。若错误减少伴随更大误改或只改善格式，则假设不获支持。
- **可能失败：** Monitor 与 Actor 同时误读工具；原始证据不足导致无法修复；附加审核放大错误或增加无效调用。
- **创新状态：** unverified；独立监督方向与仓库已有工作重合，需先对照现有实现和失败记录。
