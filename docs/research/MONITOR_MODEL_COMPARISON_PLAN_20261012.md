# Monitor 跨模型审核对照方案（待执行设置确认）

2026-10-12。用户要求拟方案，已选择通过API使用DeepSeek V4.1 Flash作为对照模型。以下按DeepSeek官方直连接口拟定；实际账户是否使用第三方转接尚未核实。本轮只完善方案，不构建新评测输入、不调用推理API、不连接服务器、不启动推理，不预判另一个模型一定更强。

## 要回答的问题

保持完整工具证据、Actor轨迹和审核指令相同，另一个模型能否发现当前8B遗漏的错误，同时不错误否定合理推理？

目标是找到值得继续验证的审核基线。比较的是两个模型及其固定推理配置的实际表现，不能把差异仅归因于参数规模；不评估最终真假准确率，不据此部署在线干预。

已有事实：[上一轮](../../experiments/faithbench_monitor_v0/automatic_audit_v1/REPORT.md)的完整文字审核，8B漏掉全局非方向证据误用和无依据的一致综合；输入4306、输出478、无截断。以前也做过[8B/27B v2比较](../../experiments/faithbench_monitor_v0/pilot_v2/RUN_REPORT_27B_20261009.md)，27B仍有语义误判，且量化/后端不同。此次不能宣传为首次换模型，也不能重复用接口通过率代替审核质量。

### DeepSeek官方文档核对（2026-10-12）

[官方模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)将 `deepseek-flash` 对应至DeepSeek-V4.1-Flash。该名称为服务别名，不能当不可变权重快照；运行时记录日期、请求ID、响应model及可取得的版本信息，若官方映射改变则先报告。用户选择的是模型，不代表已核实其账户路由。

按[官方思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，建议请求显式设置 `thinking: {type: enabled}` 和 `reasoning_effort: high`（后者为当前默认档位），本轮不额外比较关闭思考或max。思考模式的temperature不起作用，不用temperature=0声称greedy；暂不传温度、penalty、seed或额外采样参数。此为待冻结的配置建议，尚未运行。两条件仍用相同消息正文，允许模型自身推理配置不同，结论限于实际配置对照。

以最终 `content` 作为审核反馈评价对象；服务返回的 `reasoning_content` 分栏保存为运行材料，不把其存在或长度算作审核正确，也不将其送给下一例或Actor。官方请求参数参考页本次两次抓取超时，`max_tokens`与思考/可见输出的具体预算关系尚未核实，执行前必须补齐；不猜测可分别限制，也不沿用A的1024作为B总生成预算。

B通过独立、无历史的API请求读取材料。不能使用当前已经看过错误答案的对话作为对照，也不让B读取项目文档、审核记录、其他案例答案或互联网。仅传冻结的system/user消息，不给工具、不建跨案例会话、不提供纠错回合。

两条件system和user正文逐字相同；使用各自必要的原生聊天模板，记录实际请求体及正文SHA，不声称跨tokenizer的token序列相同。沿用最新通用审核提示和四项中文输出要求，不预先提取可疑主张，不恢复旧复杂JSON协议。

B采用预先选定的固定推理配置，不默认greedy等于可复现。只传API实际支持的温度/seed等参数；不为模仿A强行填入不支持的配置。若API输出预算包含内部推理，不能把总预算直接设为1024导致可见回答被挤掉：执行前根据服务文档分别定内部/可见预算，记录上限与usage。若无法分开限制，明确报告计算与输出预算不等，结论限于整套配置的能力参考。不要截断原始输出后假装等预算。

## 先冻结判据，再看模型回答

每例预审表与模型messages分开保存，至少包括：

1. 当前可见的工具事实、能力限制与动作预算。
2. 错误例的必要问题清单及可核对原句；合理例的支持理由与哪些内容只能标无法核实。
3. 可接受的替代论证、需保留的有效证据，以及禁止的过强指控。

E1严格沿用上一轮两个核心问题，不因换模型调整；局部强度校准仍为独立观察项。其余案例在运行前完成具体判据，不用API模型生成自己的标准。现有silver/助手审核只作为材料，不升级为独立gold；争议须在运行前请用户裁决或将案例排除并重新确定冻结清单。

每份输出分别记：

- **定位：** 是否发现预定必要问题，是否正确对应步骤与Actor原句。
- **理由：** 是否以实际返回/能力限制支持判断，是否出现伪造引用、错归步骤或错误推断。
- **反馈：** 错误例是否能指导修正、保留有效证据、遵守预算；合理例是否允许保持合理提议。
- **误伤：** 是否额外指控本来有依据的推理、把未知当错误，或仅因未用完工具就强制继续。

只说“有问题”、复述规范、猜对图像真假都不算通过。格式另记；截断、拒答、空输出和服务故障保留在结果表中，不从分母静默删除。模型提供预审未收录的新问题时，先核原文并记录争议，不能仅因不在清单就判误报；若需修订判据，对两模型对称重审并保留修订历史，不改写成预先设定。

## 请求数、顺序与开销

拟6例×2条件=12份输出，每例每模型一次，无自审、多数投票、反馈重试或结果驱动改提示。

E1的A可复用上一轮精确相同messages/模型/生成配置的原始响应，故最多**11次新增请求：A五次，B六次**。复用是历史确定配置的开发对照，不冒充当轮独立复现；其余旧局部/v2输出提示不同，不计入本轮。复用条件核不一致时先报告，不自动增加第12次请求。

冻结6例后以seed20261012生成两条件各自的运行顺序，每例独立上下文。A可一次加载连续执行五例，B按冻结顺序请求；记录批次/时间和服务返回版本。随机顺序减少顺序选择，不消除API后端变化，也不建立因果显著性。

官方价格于2026-10-12核对：保守按高峰、未命中缓存计费，输入$0.30/百万tokens、输出$1.20/百万tokens；缓存和低峰折扣不用于降低预算上限。以6次请求实际输入估计I和预先确定的全部计费输出上限O计算 `USD=(0.30×I+1.20×O)/1,000,000`，并核对思考token计费口径；不能用Qwen的4306 tokens代替DeepSeek实际token数。六例和预算参数尚未冻结，当前没有可保证的总金额；第三方服务若不同价须重新列明。运行前重核官方单价。A预计4090用卡5–10分钟，以无卡准备完成和用户本轮开卡为前提；API推理不要求服务器保持开卡。首轮不做重复运行来估稳定性。

API传输只包括经审阅的冻结文字请求。执行前确认服务/endpoint、该批材料的研究使用及外发范围；Git忽略不代表已获外发许可。API密钥通过已有安全凭据或环境变量读取，不写进方案、代码、日志或命令参数。不为检查接口预先发送私有案例。

明确未提交到服务的连接错误可恢复；若超时后不清楚服务是否已生成，先查request ID/服务状态，无法确认时记录缺失并停在该项，不自动重复付费请求。格式或语义失败一律保留，不重采样。

## 审阅与决定

输出保存原样，另做隐藏模型名称和随机展示顺序的审阅副本；不改正文。预审者可能熟悉案例，文风也可能暴露模型，因此称“隐藏模型标识的助手审核”，不声称真正双盲或独立人审。是否由用户再核争议须单独记录。

最终报告给出逐例A/B的定位、理由、反馈、误伤、长度、费用及缺失原因，再按来源组和终态/前缀汇总。只报告配对修复与新增错误，不做小样本显著性检验，不把多个引用或两个同源错误当独立重复。

预定工程决策（不是统计显著性门槛）：

| 观察结果 | 本轮之后如何处理 |
|---|---|
| B三错误例均通过定位+理由+反馈，三合理例无实质误伤，且修复至少一个A失败（包括E1两核心问题） | 认为找到值得下一轮独立验证的候选；仍不声称可靠部署、稳定或检测收益，不自动蒸馏/接Actor |
| B部分修复，但仍漏检、错引或误伤 | 记录具体能力差异；不以“换模型成功”概括，不直接推进训练。先讨论剩余失败是否值得继续 |
| B也遗漏E1核心矛盾或总体无清楚改善 | 暂停当前自动审核路线的工程追加，回到证据可判性、任务设置及模型行为的讨论；不据此宣称所有模型/方向不可行 |
| 两者都表现良好或基线在其他例上很好 | 记录任务异质性；不能把E1失败外推为8B全部能力不足 |
| 材料判据未决、费用/模型未锁定、输出大量截断或服务异常 | 本轮比较不完整；报告阻碍，不按语义失败解释，不自动扩预算或更换B |

所有情况均在保存、审核、报告、更新进度后停止。后续是否扩大独立样本、测试重复稳定性或让Actor接收反馈，另行讨论。
