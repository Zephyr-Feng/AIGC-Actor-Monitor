# 本地 Monitor 重训练方案 v1

日期：2026-10-16。状态：可审阅方案，尚未批准执行批次。用户确认制定方案，不等于授权新推理、教师 API、训练或新数据分配。

## 1. 推荐路线与范围

冻结 Actor 和取证工具，先验证本地基座的核查能力，再训练一个既能核对依据、又能给出修正建议的 Monitor。第一轮采用普通监督微调（SFT）；可靠性通过后，才考虑根据固定 Actor 的实际修复结果训练反馈偏好。

主线：旧结果去重审计 → 有界基座诊断 → 核验监督与分组 → 一次新 adapter SFT → 独立来源验证 → 修正反馈训练与闭环。各阶段有独立停止点，不自动串行执行。

- FULL20 禁止重跑；其历史结果只作背景，不用于这次选模型、调参或新闭环。
- Actor-B 权重、提示、工具协议与调用上限保持当前冻结版本；不把 Monitor 训练混作 Actor SFT。
- 当前优先解决工具返回忠实性和能力边界错误。视觉主张单独标记为需要图像，文本阶段不强行判真伪。
- 不读取或分配尚保留的 44 来源组，不读 GT，不新增假图，不自动访问服务器。测试来源需另行确认。
- 旧 adapter、raw、评分和实验目录保持原样。任何新 adapter 单独保存，不覆盖默认模型。

## 2. 为什么不能只是“再训一遍”

已有事实：

1. [v3](../../experiments/faithbench_monitor_v0/sft_evidence_contract_v3/REPORT_20261010.md)中格式有效率改善，但编号被当作对象描述、检查数被当作全称结论依据、缺失列表被错误处理。
2. [关系 SFT 追溯](../../experiments/faithbench_monitor_v0/pilot_v3/REPORT_RELATION_SFT_POSTHOC_AUDIT_20261011.md)证明第三值缺失已进入监督，并非漏训；36 个未覆盖题型上基座联合通过 34/36，关系 adapter 为 28/36。该组不是新的独立测试。
3. [紧凑绑定预检](../../experiments/faithbench_monitor_v0/pilot_v3/REPORT_BINDING_COMPACT_PROBE_V1_20261011.md)已尝试结构化绑定，存在输出超预算和缺失条件误判。增加字段本身不构成新方法。
4. DeepSeek 的开发表现说明文本信息足以解决部分问题，但不同模型的推理预算、提示与后端差异尚不能被归因成纯参数规模效应。

本方案不预设根因，不声称缺图片、步数少、判断 token 占比低或 q/v LoRA 是已证实的原因。新增价值在于：监督可核验、来源分组、对语义保持与关键条件改变分别检查、按自由生成选模型、明确退化停止条件。成对/缺失监督过去已有，必须审计具体覆盖与迁移差异，不能把相似模板扩增当新能力。

## 3. 阶段 A：先决定当前基座是否值得重训

### A0：仅整理已有结果，不调用模型

按模型版本、adapter、完整 prompt、可见证据、生成预算、量化/后端建立结果索引。精确匹配的已有输出直接复用；没有匹配的格子才列入拟议推理。先核查基座与 adapter 是否曾在同输入上比较，避免重复已有诊断。

建议诊断材料来自已曝光、已获准使用的开发材料，候选 12–18 个不同主张，覆盖：数值/阈值、同对象字段、全称/数量、缺失、工具语义归因、非方向性边界；包含正确主张和未决情况。不声称现成库存一定满足配额，不为凑数读取预留组。

### A1：最多两种本地权重 × 两种输入视图

- 权重：当前原始基座；与其兼容、可追溯的一个旧 adapter。旧 adapter 仅作诊断，不选“最好看的”历史版本。
- 视图：完整的当时可见文本材料；人工核验的精简材料。
- 精简材料必须保留决定性值、来源范围、必要缺失和工具定义。删掉唯一阈值或只保留 top-3，不能作为与原题等价的简化。
- 输入、解码、输出契约尽可能一致；旧输出不符合当前条件就只作历史背景。输出过长/截断单列，不补采到成功。
- 精简输入有人工定位优势，只能诊断条件化能力，不是可部署结果。
- 12–18 主张对应最多 48–72 个本地输出，再减精确复用量。DeepSeek 历史输出只作参考；本阶段默认零新教师 API。

决策：精简仍反复发生核心错误，先暂停该基座 SFT，另拟最多一个替代本地基座比较；精简可行、完整失败，先改善输入中的来源标识/任务聚焦；基座好而 adapter 差，从基座新建 adapter。长短输入差异只是候选解释证据，不直接证明内部机制。

基座选择：现有 Qwen3-VL-8B-Instruct 是诊断起点，不是已选定的最终 Monitor。保留未来多模态接口，但第一轮不以“将来要看图”为由训练视觉模块。替代型号、许可证、权重格式和训练兼容性另核；不把现有 27B GGUF 推理权重当作可直接微调权重。

## 4. 阶段 B：先做可复核监督包

### 标注对象与输出

第一层针对一条明确主张，输入包括该主张、原始来源、当前工具定义及必要上下文。建议短输出：主张位置、决定性引用、关系判断、一句理由。引用可多个，必须附来源和对象身份；并不要求模型输出长思维链。

区分两个问题，不挤进一个标签：

- 内容支持关系：支持 / 矛盾 / 信息不足。
- 来源归因：忠实 / 不忠实 / 无法核验。

例如完整工具返回未描述云层：“工具报告了云层异常”的归因不忠实，但图中是否真有云层异常仍可能无法核验。若来源包本身不完整，则不能断言工具一定没有描述。阶段 A 诊断不能因为换标签体系就与旧分数直接比较；以上是新候选契约，实施前映射并复核。

第二层必须包含完整材料中的自主主张定位与审核，训练时不给人工选出的答案位置。否则学到的只是“给定主张的核查器”，还不能替代完整 Monitor。建议同一模型使用两种任务指令，第一轮采用混合 SFT，不建两个独立大模型。

### 数据组成建议

先审阅少量标注样例，再决定规模。首轮资源规划可按 **150–300 条经核验监督**估算，而非几千条自动蒸馏；这不是统计功效结论，也不是现有独立来源数量。约 2/3 单主张核查、1/3 完整材料审核，具体比例随库存确认；两类都要有错误、合理和未决，不能只有纠错正例。

优先复用原始开发材料与已核验目标，保留旧错误输出作为候选负例但重新确认标签。DeepSeek 的短反馈可作待审草稿；不直接蒸馏长推理，不把教师判断当 gold，不要求新增 API。来源不足则缩小为开发 pilot，不能靠同一来源的数百变体宣称规模扩大。

两种成对样本：

1. **改变决定性条件，标签应改变**：第三值高于阈值/低于阈值/缺失；声明数量与实际完整列表一致/不一致。遵守可实现的统计关系，不制造 max、median、计数互相矛盾的“正例”。
2. **保持语义，标签应不变**：合法编号重命名、顺序变化、中性表达替换；引用映射和对象身份必须一致。优先覆盖旧失败中实际观察到的变化，不无限组合扩增。

受控变体要标 synthetic_control，与真实工具日志分开保存。不能把修改后的工具能力冒充真实 PROBE 协议；测试其他工具定义时明确为抽象练习。GT、未来工具结果、其他条件反馈、参考答案及带标签文件名不得进入输入。

### 分组和参考答案

先按原始来源组、图像派生关系和控制模板谱系形成隔离组，再划训练/开发/最终测试，之后才生成变体。所有同源视图/主张/变体同组；跨来源同模板的迁移另报告，不冒充模板外泛化。

已被反复查看或用于决策的 36 题、D1/D2、自然30等只能作为开发/回归材料。是否加入训练必须明确登记；一旦加入，不能继续称其未见评价。44 保留组不自动用于测试。

标注保留原始引文、判据、版本、复核者和争议。研究者复核关键判断，争议保留未决；没有独立人审时报告“助手辅助开发参考”，不叫 gold。若无法找到合法隔离的测试组，则首轮只能得出开发诊断，停止总体有效性宣称。

## 5. 阶段 C：第一轮训练配置与 loss

下表是供确认的起始配置，不是经过调优的最优配置，也不是启动指令。

| 项目 | 建议起点 |
|---|---|
| 初始化 | 通过 A 阶段的原始基座，新建一个 adapter |
| 参数更新 | 仅语言模块 LoRA；视觉模块冻结 |
| 精度 | 若仍为单张 24GB 卡，沿用已验证的 NF4 + BF16 路径；须先核当前环境与显存 |
| LoRA | 首轮沿用历史 q/v、r=8、alpha=16、dropout=0.05，尽量减少配置同时变化 |
| 优化器 | AdamW；候选学习率 5e-5，作为比旧 2e-4 保守的试点，不声称能消除退化 |
| batch | micro-batch 1，梯度累积 8；记录实际有效 batch 和余数处理 |
| 训练上限 | 最多 3 遍，每遍保存；固定一个训练 seed，首轮不做参数网格 |
| 选择模型 | 基座及每遍检查点自由生成；按开发联合正确与误伤选择，不按最低训练 loss |
| 长度 | 完整分词后设置；禁止静默截断来源或标签，过长先返回数据准备阶段 |

第一轮采用 assistant-only 的 token 交叉熵：

`L_SFT = - mean_t log Pθ(y_t | x, y_<t)`，只统计目标输出 token。

训练目标短且可核验；不额外加入推测性的“推理 loss”。同时记录判断、引用、理由各部分的 teacher-forced loss 作为诊断，并以自由生成检验真正能力。字段 loss 低不保证完整输出正确，整体 loss 低更不能替代评价。

技术预检沿用现有准备/训练脚本的 chat prefix、assistant mask、长度、adapter 非零更新、冻结权重与备份核验；首次新运行需核训练时与重新加载后的推理一致性。检查失败停止，不靠追加训练掩盖问题。

这里只能评价新数据与配置组成的完整方案，不能把改善归因于单独降低学习率。若以后要研究字段加权 loss，需同数据、同初始权重、同曝光与推理预算对照常规 CE；先有字段错误证据，再选择权重。LoRA 扩到 q/k/v/o 或更大 rank 同理，不与 loss 一起扫参。

## 6. 验收与停止条件

主指标为每条主张的**判断、决定性证据、理由同时正确**，任一错不算完整通过。额外报告：完整材料核心问题召回、正确内容误伤、未决被强断言、虚构引用/字段、能力越界、非法接口/截断和 token 成本。

“少说、都说未知、删除整段”不能得高分：合理主张保留率、明确错误召回和未决处理分别报告。成对变体要求该变时变、该不变时不变，不能只看平均标签匹配。

建议的首轮工程门槛（待确认，非统计有效性证明）：

- 预锁定核心哨兵中，虚构缺失值、把非方向分数说成真假票、越预算建议三类严重错误为 0；哨兵不能全是训练原题。
- 在相同开发材料上，联合正确不低于原始基座，且至少修复一个预指定失败；正确内容误伤和未决强断言均不增加。
- 如样本充足，可另预注册实际有用的改进幅度；本稿不凭空指定“达到90%即可部署”。
- 任一检查点新增严重错误或主要指标下降，不晋级。所有检查点都未通过则记录失败，不自动加 epoch、换学习率或换基座。
- 开发通过后冻结模型、prompt、预算和判据，再运行另行批准的隔离来源测试。失败后测试集转开发，不能反复调到通过仍叫独立测试。

最终按来源组汇总配对改善/退化与不确定性；同图多主张、多种变体、多个检查点不是独立样本。首轮单 seed 无法证明训练稳定性；正式结论前需另行规划独立来源规模与训练重复。

## 7. 阶段 D：从可靠审核到可执行反馈

只有 C 通过才进入。用经核验的诊断训练短修正计划：目标句 → 原始依据 → 撤回/缩小/补充建议 → 应保留的正确内容。无错误可不干预；无工具预算不能建议非法调用；不替 Actor 指定真假标签。

先用同一个本地模型生成计划并测一次冻结 Actor 的反馈执行。训练参考诊断输入和部署时自身诊断存在差异，因此必须报告两种条件：给定正确诊断的计划能力；自身诊断到最终 Actor 输出的端到端能力。

后续偏好训练候选：同一状态下两条合法、证据正确的反馈，经相同 Actor 配置执行后比较。优先无新增错误/无正确内容丢失，再比较原错误修复；结果互有优劣或标注不确定则不造偏好对。这样避免用任意加权总分掩盖误伤。DPO 的 reference 冻结为通过验收的 SFT Monitor，可保留审核 SFT 回放防退化；是否需要、权重多少由实际退化证据决定。

闭环至少比较无反馈、本地基座反馈、本地 SFT 反馈；若研究 DPO，增列同一个 SFT 反馈对照，Actor 和允许预算一致。评价推理修复、内容保留、接口合法及最终检测损害，分别报告；检测评估中的 GT 使用需另批准，与模型输入隔离。

反馈效用学习参考 [CTRL](https://arxiv.org/abs/2502.03492) 的固定生成器思路；其代码任务执行判据不能直接移植为本项目自动真值。[DPO](https://arxiv.org/abs/2305.18290) 是成熟偏好优化方法，不构成本项目单独创新。潜在研究贡献需落在证据约束和实际修复机制，并经对照支持。

## 8. 图片输入的安排

工具忠实性任务先完成文本基线；对视觉事实的核查保持未决。之后若加入图片，在同一多模态基座上比较文本与文本加图，使用 Actor 当时可见原图/合法裁片，不引入未来信息。

视觉正确和工具归因忠实分别评分：图片确实有云，不代表工具曾报告云。若同步改变模型和输入模态，不能把提升归因于图片。加入图像后需重新验收文字核查回归，不能假定只会改善。

## 9. 执行批次、资源与交付

| 批次 | 交付 | 资源与边界 |
|---|---|---|
| A0 本地准备 | 已有输出索引、缺失比较清单、标签与判据草例 | 无模型/API/GPU；实际样本读取范围确认后进行 |
| A1 有界诊断 | 配对输出、原因分类、是否保留基座 | 候选最多48–72输出，扣除可复用；不追加 DeepSeek |
| B 监督包 | 来源/许可/曝光清单、分组清单、核验目标 | 150–300条仅规划上限范围；无自动扩写/保留组读取 |
| C 一次SFT | 新adapter、基座与最多3个检查点结果、失败/晋级报告 | 一次训练；评估量=(1+检查点数)×冻结评价条数，精确冻结后执行 |
| D 反馈与闭环 | 计划训练/偏好对、Actor配对结果 | 不计入首批；独立方案与用卡确认 |

不能据旧短样本训练时间承诺新批次时长。A1 用现有日志按实际输入/输出量估算后向用户报告预计开卡窗口；C 在材料长度、评估数量和当前硬件核验后给出时长及硬上限，获确认再运行。训练与Actor推理串行加载，避免默认单卡能同时容纳两模型。任务结束核自有进程退出并通知关卡。

实现优先复用 `sft_evidence_contract_v3/prepare.py`、`run.py`、`contract.py`，以及 `pilot_v3/run_relation_sft_comparison_v1.py` 的已核验打包/遮罩/记录方法；不直接运行旧脚本，因为其中绑定旧样本数量、协议和预算。实施时另核依赖及调用范围，新增最小薄改动，保留旧冻结文件。

公开资料先复用已整理的[反馈文献与方案](MONITOR_FEEDBACK_LITERATURE_AND_OPTIONS_20261015.md)。本轮没有发现并核验可直接替代项目工具契约监督的公开数据集，不下载或纳入未经许可核对的数据；采用公开权重/代码/数据前分别登记许可和适用差异。

当前建议先确认 A0/A1 的来源范围与对照配置，不要求一次批准整个路线。模型版本、标注人、独立测试来源、首轮配置与算力预算均未冻结。
