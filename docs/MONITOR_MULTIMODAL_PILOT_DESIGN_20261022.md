# Monitor多模态整稿审核：下一轮训练方案

2026-10-22。设计稿，未执行。本版替代早期96条/12步设想；方案不构成执行授权。

## 目标与证据边界

检验从00373继续进行图文整稿监督，能否提高完整反馈正确率，同时保护正确内容、未知判断和真实工具关系。主要假设是图像通路与整稿监督共同改善审核；竞争解释是模型只记住构造模板，领域问题仍在证据理解或Actor采用阶段。

本轮只评价整体配方，不单独归因于图片。现有开发50条全部是公共来源；本地11个取证来源全部已曝光并在训练集。因此公共开发改善不代表自然取证泛化，领域训练内成功也不代表对Actor有净收益。

依据：[数据卡](../data/monitor_multimodal_dataset_v1_20261022/DATASET_CARD.md)、[旧版失败复盘](../data/monitor_complete_pair_v1_20261021/execution_80/OLD_MONITOR_DIAGNOSIS.md)。复用已完成的材料审阅和文献核对，不重下载、不扩充同源改写。

## 数据与监督

只使用最终train.json的332条、63来源组；development.json的50条、12组只作开发诊断。领域110条，公共训练222条；按原有分组不重新分配。每遍每条恰好出现一次，固定种子20261022洗牌，不重采样、不加入未审公共池。

输入为原图（或明确缺图）、完整候选回答、真实工具返回和审核边界。目标沿用中文“结论/问题/保留/说明”。完整覆盖跨字段同一错误；逐句定位，给最小修正建议。图像判断可见事实，工具返回确定数值与方向；未知不编造、真实冲突不抹去，外观不能认证来源真伪。

只对assistant目标计算loss，屏蔽system/user、图片及padding。沿用逐样本目标token平均再对样本平均，避免长领域反馈仅凭长度占据全部梯度。分别记录领域/公共、pass/revise/uncertain的监督量和loss，不以loss作为语义成功。

## 训练配置

|项|拟定值|
|---|---|
|初始化|00373；核实既有adapter实际加载方式|
|训练参数|只更新既有语言LoRA，r=8；冻结基础权重、视觉编码器和连接部分|
|精度与优化|沿用既有QLoRA与优化器；学习率1e-5，不增加新优化机制|
|批大小|微批1，梯度累积8；单GPU，不做样本拼接|
|预算|最多3遍，996次样本呈现；每遍42更新，共126更新|
|末批|每遍最后4条单独更新，按实际4条归一化；不可仍除以8|
|检查点|42、84、126更新；完整保存训练配置、顺序与日志|
|输入|每题一张原图，无额外裁剪；暂定视觉token≤512、总序列≤4096|
|生成|greedy，输出上限1280 token，各比较条件一致|

三个检查点是学习诊断，不是三个超参数试验。最多只训一份候选，不扫描学习率、rank或随机种子。126步意味着每条最多看三次，不意味着新增独立证据。

原生processor预检如发现完整输入或目标超限，应先调整并重新冻结长度/图像预算，不能静默截断后继续。以上长度是拟定值，尚非可运行性结论。

## 执行顺序与调用上限

1. **预检，0更新、0生成。** 用Monitor自己的processor核对全部332条实际长度和目标完整性；以有图、缺图、最长领域样本检查mask、图片网格、前向与反向、有限loss及可训练参数。反向后清梯度，不执行optimizer.step。复用现有图片桥接，旧纯文本训练器不可直接运行。先核GPU，只处理自有任务；脚本若无法避开任何哈希核验则不运行。
2. **旧版基线，50次生成。** 00373按50条开发数据各自原有可见性生成，保存全部原始输出。此处建立当前输入条件基线，不复用条件不同的旧成绩。
3. **训练与训练内检查，最多24次生成。** 执行至42/84/126更新，每次检查预先固定的8条训练题。第一次不通过可以继续至下个预定检查点；不把早期未学会直接判为无效。若满足下述门槛，立即停止并选择该最早检查点。126步仍未通过则停止，不自动加epoch。
4. **一次开发比较，50次生成。** 仅对所选候选运行完整50条，比较旧版基线。不能根据开发分数回头换checkpoint或追加训练。若训练内未通过，本阶段跳过。
5. **图片依赖诊断，最多24次生成。** 提前从开发集选12条有图题，每来源至多1条；旧版和候选各生成其缺图版本。有图结果复用前两阶段，不重复生成。缺图参考改为恰当未决，不能直接用图像答案打分。若不足12个合适来源，缩小数量并记录。

总上限：1次训练、126更新、148次Monitor生成；Actor生成、教师API、新取证工具、图片生成均为0。阶段5用于解释视觉作用，不作为二次选型。

训练内8题在生成前按覆盖选定ID：领域6题覆盖自然原稿、多字段global、真实冲突/信号、计数、未知、正确保留；公共2题覆盖视觉纠错和缺图未决。尽量各用不同来源。以现有标签选题，不看模型输出选题。通过门槛：完整反馈至少7/8，未知、正确保留和真实冲突指定项全部通过，无有害建议。未决目标按其参考判断，不强迫确定结论。

拟定训练进程上限7200秒、单次生成180秒、全流程21600秒。超时/OOM/非有限loss或监督边界错误立即停并查原始日志与自有进程，不盲重启；无训练/生成自动重试预算。实际速度若不满足预算，先报告并重新设计，不能偷偷延长。

## 开发评价与决策

主要指标为完整反馈正确率：覆盖全部可核实主要错误，建议一致，正确内容与未知边界保留。辅助报告逐位置覆盖、误报/有害建议、格式失败和截断。所有缺失、失败和争议原样保留，不能删题美化分数。

逐条审阅时隐藏模型条件，按预先固定参考判断；仍为助手开发审阅，不称人审gold。同时报告按12个来源等权的分数与来源配对胜负，避免同源变体虚增证据。构造题与原始候选题分开报告。

进入下一阶段的开发门槛（工程筛选标准，不是统计显著性）：

- 候选完整反馈至少40/50，较旧版净增至少5/50，至少2个不同来源改善且无来源退化。
- 不新增有害建议；正确保留、来源未知与缺图克制均不退化。
- 训练内领域6题至少5题完整通过，且指定保护项全部通过；只称训练内证据。
- 若旧版本已达到45/50以上导致提升空间不足，报告天花板，不能临时降低增益门槛或换题追求过关。

通过后才能提出下一轮自然取证开发方案：优先寻找未用于本轮训练且用途已授权的自然原稿；不足则如实报告来源缺口，不挪用GT44/保留身份或冻结集。随后才设计固定强Actor同条件自审对照，分开记录Monitor识错、Actor采用、原始修订与接口回退。当前148次预算不含这些后续工作。

若训练内成功而公共开发不改善，优先判断过拟合/领域不匹配；若公共视觉改善而领域整稿仍失败，转查关系监督；若未来反馈正确但落地失败，处理采用/接口。不能用更多epoch统一解释这些不同失败。
