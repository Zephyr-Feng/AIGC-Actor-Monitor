# Actor Monitor：面向多模态图像取证的轨迹条件干预

**项目主方案，MVP v1.0**  
更新时间：2026-09-27

## 1. 核心 idea

多模态取证 Actor 在给出最终答案前，通常已经形成初步判断、证据摘要、工具观察和不确定性表达。不同错误可能需要不同的处理方式。有些样本适合重新核验证据，有些样本适合考虑相反假设，还有一些样本不需要干预。

本项目研究：

> Monitor 能否根据 Actor 的干预前轨迹，选择不干预、证据核验或替代假设推理，从而比固定使用某一种干预更可靠？

项目重点是**根据轨迹选择合适的动作**。工具和 Actor 都是形成研究环境的组成部分，不单独构成论文主线。

## 2. 研究问题与假设

### H1：不同干预对不同样本具有互补作用

`A1` 可能纠正证据读取错误，`A2` 可能纠正过早判断，而 `A0` 可以避免不必要干预造成的误伤。如果同一个固定动作对几乎所有样本都最好，就没有必要训练 Monitor。

### H2：干预前轨迹包含动作收益信号

Actor 的可观察轨迹 `Z` 包括初步判断、置信度、证据摘要、工具结果及其冲突。Monitor 使用这些信息预测每种动作相对 `A0` 的收益。

### H3：轨迹条件选择优于固定动作和简单规则

在相近的干预比例或 token 预算下，Monitor 应当优于：

- 永不干预；
- 始终使用 `A1` 或始终使用 `A2`；
- 随机选择动作；
- 只根据置信度或不确定性触发的规则。

其中，**Monitor 是否优于最佳固定动作**是检验本项目核心 idea 的主要比较。

## 3. 整体框架

```text
Image
  |
  v
Forensic Actor
  |
  |  preliminary answer + observable trajectory Z
  v
Monitor
  |
  |  choose one action
  v
A0 No intervention | A1 Evidence verification | A2 Alternative hypothesis
  |
  v
Final answer
```

本 MVP 只研究一个固定检查点：Actor 已经形成初步判断，但尚未提交最终答案。更早或更晚的干预时机留作后续研究。

## 4. Actor 的初步处理

选择一个固定的多模态大模型作为 Actor，并在整个主实验中冻结模型版本、系统提示和解码设置。

Actor 对每张图像执行以下流程：

1. 查看图像；
2. 读取同一组固定取证工具的结果；
3. 形成初步判断；
4. 输出可观察的判断依据和不确定性；
5. 在最终答案前进入 Monitor 检查点。

建议保存：

```json
{
  "preliminary_answer": "real/fake",
  "confidence": 0.70,
  "evidence_summary": ["..."],
  "tool_observations": ["..."],
  "uncertainty": "..."
}
```

这里记录的是 Actor 的**可观察轨迹**，不把生成的解释文本等同于模型内部思维过程。

Actor 的初步判断、证据摘要、不确定性和最终解释均使用中文。`real` / `fake` 仅作为机器可读标签。固定检查点前先要求 Actor 按以下字段给出尚未提交的判断，随后保存完整前缀：

```text
初步判断：real 或 fake
置信度：0 到 1 之间的小数
证据摘要：用中文说明支持判断的具体图像现象；只有已提供工具结果时才引用工具读数
不确定性：用中文说明仍可能推翻判断的证据或局限
```

### 工具的最小可用性检查

工具结果只作为证据，不作为真值。MVP 开始时用约 20 至 30 张图进行一次小规模检查：

- 比较 Actor 只看图像与 Actor 同时看到工具结果时的表现；
- 检查工具是否能够稳定运行，是否大量缺失或持续误导 Actor；
- 只保留两到三个可以正常使用的工具，并在所有样本上提供同一工具集合。

该检查只用于确定 Actor 的输入配置，不扩展成独立的工具研究项目。

T0 检查后，经用户确认，后续配对采集固定使用压缩/DCT、噪声残差、纹理/LBP 三类工具，共 9 项原始读数。真图参考区间仅用于描述分布，Actor 不得把落在区间内直接解释为真实，也不得把区间外直接解释为伪造。T0 观察与选择依据见 [T0_TOOL_CHECK.md](T0_TOOL_CHECK.md)。

## 5. 三种动作

### A0：No Intervention

不加入纠错提示。Actor 按照当前判断生成最终答案和中文解释。

### A1：Evidence Verification

目标是纠正工具读取错误、证据引用错误和忽略已有证据的问题。

```text
请核验当前判断的重要依据是否得到已有图像现象和实际提供的工具结果（如有）支持；如有证据引用或解读错误，请在最终回答中修正。
```

### A2：Alternative Hypothesis

目标是纠正过早判断和单一假设驱动的推理。

```text
请考虑最有力的另一种解释，比较这张图像可能是真实拍摄或 AI 生成的理由，再作最终判断。
```

三个动作共用同一份最终回答要求：给出 `real` / `fake` 结论、具体证据与结论的关系、关键不确定性和置信度；解释必须使用中文。以上提示在正式采集前固定，且不得包含图像真值或目标答案。

## 6. 同轨迹分支与动作收益

对每个样本，Actor 只运行一次检查点以前的过程。保存同一个干预前轨迹 `Z_i`，然后分别执行 `A0`、`A1` 和 `A2`：

```text
same Z_i
├── A0 -> final answer
├── A1 -> final answer
└── A2 -> final answer
```

令 `R_i(a)=1` 表示动作 `a` 下回答正确，`R_i(a)=0` 表示回答错误。动作相对不干预的收益定义为：

```text
Delta_i(a) = R_i(a) - R_i(A0)
```

因此：

- `Delta=1` 表示干预把错误改成正确；
- `Delta=0` 表示结果没有变化；
- `Delta=-1` 表示干预把正确答案改错。

若资源允许，每个分支使用两个预先固定的解码 seed；资源有限时先使用确定性解码完成 MVP。训练集、验证集和测试集严格分开，测试集只用于最终评价。

## 7. Monitor

### 输入

Monitor 只能使用动作执行前已经存在的信息：

- 初步答案与置信度；
- 不确定性表达；
- 证据摘要长度和结构；
- 工具之间的分歧；
- Actor 判断与工具证据之间的冲突；
- 工具调用次数与已有 token 使用量。

### 输出与决策

Monitor 分别预测：

```text
Delta_hat_A1(Z), Delta_hat_A2(Z)
```

`A0` 的相对收益固定为 0。只有当某个干预动作的预测收益高于 0 或验证集确定的阈值时，Monitor 才选择该动作，否则选择 `A0`。

MVP 优先使用低容量、容易解释的模型，例如正则化回归或小型树模型。模型复杂度本身不是贡献重点。

## 8. 数据集

数据划分为训练集、验证集和测试集，并满足：

- real 与 AI-generated 样本基本平衡；
- 训练集包含多个生成器；
- 同一原图或其近重复版本不得跨集合；
- 测试集保留一部分训练中未出现的生成器，用作辅助 OOD 评价。

主结论来自固定 Actor 上的独立测试集。跨生成器结果用于观察泛化，不扩大为跨所有 Actor 或所有取证任务的结论。

## 9. 实验设计

### Experiment 1：三种动作是否具有互补性

在配对分支结果上报告：

- `A1` 和 `A2` 各自纠正了哪些错误；
- 各动作造成了多少正确到错误的误伤；
- 不同样本的最佳动作是否不同；
- 最佳固定动作与逐样本 oracle 之间还有多少选择空间。

这个实验先回答 Monitor 是否有存在的必要。

### Experiment 2：Monitor 能否选择更合适的动作

主要比较：

| 方法 | 动作方式 |
|---|---|
| Actor / A0 | 从不干预 |
| Fixed A1 | 所有样本都核验证据 |
| Fixed A2 | 所有样本都考虑替代假设 |
| Random | 按相同干预比例随机选择 |
| Confidence Rule | 低置信度时使用验证集选定的固定动作 |
| Monitor | 根据轨迹选择 A0、A1 或 A2 |

Monitor 与规则和随机策略应在相近干预比例或相近 token 预算下比较，避免把更多计算本身误认为更好的选择能力。

### Experiment 3：Monitor 使用了哪些信息

进行三个简单消融：

- 去掉置信度；
- 去掉工具和证据冲突特征；
- 只保留置信度与初步答案。

该实验用于解释 Monitor 的信息来源，不作为主贡献。

## 10. 评价指标

主要指标：

- Accuracy 和 macro-F1；
- Monitor 相对 `A0` 的准确率增益；
- Monitor 相对最佳固定动作的准确率增益。

同时报告：

- Correction rate，错误变为正确；
- Damage rate，正确变为错误；
- Intervention rate；
- 平均新增 token 和推理时间。

核心成功条件是：

> Monitor 在相近干预预算下优于最佳固定动作，并且收益不是由明显更高的误伤率换来的。

结果应报告配对差值及其置信区间。具体样本量在小规模分支试验后，根据观察到的差异和可用资源确定。

## 11. 三个月计划

### Month 1：建立配对分支数据

- 固定一个 Actor 和两到三个可用工具；
- 完成工具的最小可用性检查；
- 实现固定检查点和 A0、A1、A2 同轨迹分支；
- 完成小规模配对试验，确认不同动作存在互补空间。

### Month 2：训练和评价 Monitor

- 提取干预前轨迹特征；
- 训练低容量 Monitor；
- 在验证集确定动作阈值和干预预算；
- 完成 Monitor、固定动作和规则基线比较。

### Month 3：独立测试与分析

- 在独立测试集运行冻结策略；
- 完成 OOD 辅助测试和特征消融；
- 分析 correction、damage 和成本；
- 整理论文结果。

## 12. 项目贡献与结论边界

如果主要假设得到支持，本项目的贡献是：

1. 证明多模态图像取证轨迹中存在可用于区分纠错动作的信号；
2. 建立一个根据轨迹预测动作收益并选择干预的轻量 Monitor；
3. 证明逐样本选择干预可以在有限预算下优于不干预和固定干预。

本 MVP 不声称首先提出干预收益或轨迹监控，也不回答任意时刻的干预时机。它检验的是一个更具体的问题：

> 在多模态图像取证中，Actor 的可观察轨迹能否帮助系统为不同样本选择不同的纠错动作？

这就是项目主线。
