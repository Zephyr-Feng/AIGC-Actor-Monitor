# Actor–Monitor：轨迹条件的干预收益与成本预测

**项目主方案，MVP v2.0**  
**更新时间：2026-09-28**  
**状态：Stage 0 复用审计已完成；推荐组件待用户确认后进入 Stage 1**

> v1 方案保存在 [历史快照](archive/Actor_Monitor_MVP_Protocol_v1.md)。v2 的调整依据来自 [三动作 pilot](THREE_ACTION_PILOT_CHECK.md) 与 [MLLM 加工具复用评审](MLLM_TOOL_REUSE_REVIEW.md)。旧 pilot 是方案诊断材料，不作为 v2 方法有效性的证据。

## 1. 研究定位

多模态取证 Actor 在给出最终结论前，已经形成可观察的初步轨迹，包括初步标签、置信度、证据摘要、工具观察、冲突与不确定性。对不同样本，继续接受当前判断、审计已有证据或获取额外取证证据的收益并不相同。

本项目研究：

> 在固定且公开可复用的 Actor 与取证专家环境中，Monitor 能否根据干预前轨迹预测不同动作的样本级收益与成本，并在相同干预预算下优于最佳固定动作？

本项目只把以下部分作为主要创新对象：

1. 在同一干预前轨迹上采集多个动作的反事实结果；
2. 预测动作相对不干预的增量收益与误伤风险；
3. 在调用成本约束下进行样本级干预选择；
4. 用纠错、误伤、成本、oracle gap 和 policy regret 评价选择策略。

Actor、公开取证专家、工具协议、校准方法和公开数据集优先复用已有工作。本项目不以重新训练更强检测器、发明新的底层取证特征或重建通用工具 Agent 为贡献。

## 2. 与已有工作的边界

### 2.1 复用边界

| 层级 | 处理方式 | 候选来源 |
|---|---|---|
| 基础 Actor | 冻结公开模型、提示和解码配置 | 首选延续 Qwen3-VL-8B-Instruct |
| 取证专家 | 复用并冻结公开检测器或取证 MLLM | Stage 0 首选 FSD + AIDE；AIGI-Holmes 作条件性强基线 |
| 工具执行 | 复用现有工具调用和轨迹协议，按本项目数据契约写薄适配层 | ForgeryVCR 等公开实现 |
| 工具解释 | 使用能力卡、范围审计、弃权和冲突描述 | Dissecting Agentic Forensics 等公开设计 |
| 分数校准 | 复用公开后验校准方法 | AIGI Detector Calibration 等 |
| 数据 | 优先使用公开真图、AIGI 与跨生成器测试集 | COCO、DRCT-2M、AIGCDetectBenchmark 等，具体清单另行冻结 |

表中项目均为候选，不代表已经通过许可证、权重可得性、训练集重叠、单张 4090 显存和任务适配核对。

### 2.2 与 EvoGuard 的区别

[EvoGuard](https://arxiv.org/abs/2603.17343) 已研究 MLLM 对多个 AIGI 检测器的动态选择与多轮编排。因此，本项目不把“为图像选择哪个检测器”作为核心创新。

本项目的研究单位是固定检查点后的**干预决策**：

- 是否接受 Actor 已形成的判断；
- 是否只审计当前证据；
- 是否值得支付额外成本获取预先固定的补充证据；
- 哪个动作对当前轨迹具有正的反事实收益。

正式实验应包含 EvoGuard 风格的工具路由或调用全部专家作为相关基线，但主张限定为轨迹条件干预和成本约束下的增量效用。

## 3. 研究问题与假设

### RQ1：动作是否具有互补收益

在同一个干预前轨迹上，`A1` 和 `A2` 是否分别纠正一部分 `A0` 错误，同时也对另一部分样本造成误伤？

**H1**：不存在一个固定动作支配所有样本，逐样本 oracle 的效用高于最佳固定动作。

### RQ2：轨迹是否包含动作收益信号

Actor 的初步结论、置信度、证据冲突、工具适用范围、缺失与校准状态，是否能预测哪个动作会纠错或误伤？

**H2**：只使用动作执行前信息训练的轻量 Monitor，可以在验证集以外预测动作增量效用。

### RQ3：Monitor 是否在相同成本下优于固定策略

**H3**：在相同干预率、工具调用数或推理成本下，Monitor 的测试集效用高于 `A0`、最佳固定动作、置信度规则、随机策略和调用全部专家。

若 H1 在预先定义的可行性 pilot 中不成立，则没有训练 Monitor 的前提，项目停在动作设计阶段，不用扩大样本量掩盖动作无差异。

## 4. 系统结构

```text
Image
  |
  v
Frozen Actor + frozen base evidence package
  |
  | preliminary label, confidence, evidence, conflicts, uncertainty
  v
Fixed checkpoint: observable trajectory Z
  |
  v
Monitor predicts incremental utility and cost
  |
  +---- A0 Accept current trajectory
  +---- A1 Audit existing evidence
  +---- A2 Acquire fixed complementary evidence
  |
  v
Final label + Chinese explanation + logged cost
```

本 MVP 只研究一个固定检查点：Actor 已形成初步判断，但尚未提交最终答案。更早或更晚的干预时机、开放式工具规划和无限多轮调用不属于本轮范围。

## 5. 冻结的前端环境

### 5.1 Actor

Stage 0 默认先核对 Qwen3-VL-8B-Instruct，以保持与历史 pilot 的可比性。若它无法可靠消费经过校准的结构化证据，则可以在正式 pilot 前更换为公开取证 MLLM；更换理由和版本必须记录，之后冻结。

Actor 的初步判断、证据摘要、干预提示和最终解释统一使用中文。`real` / `fake` 只作为机器可读标签。生成文本被视为可观察输出，不等同于模型内部思维过程。

固定检查点前至少保存：

```json
{
  "preliminary_answer": "real/fake",
  "confidence": 0.70,
  "evidence_summary": ["..."],
  "base_expert_observations": ["..."],
  "scope_flags": ["in_scope/out_of_scope/unknown"],
  "evidence_conflicts": ["..."],
  "uncertainty": "...",
  "prompt_version": "...",
  "model_version": "..."
}
```

### 5.2 取证专家

正式工具必须是已有公开模型或有独立数据支持的检测器。每个专家进入实验前建立固定能力卡：

- 训练任务和训练数据来源；
- 输入尺寸、编码和预处理要求；
- 输出字段、方向、阈值和校准方法；
- 已知强项、失效范围和 OOD 风险；
- 是否允许对当前样本弃权；
- 代码、权重和许可证版本。

旧 pilot 的压缩/DCT、噪声残差、纹理/LBP 共 9 项读数降级为诊断性特征。除非独立验证证明其目标域效用并完成校准，否则不进入正式基础证据包。

### 5.3 基础证据与补充证据

为避免把项目重新变成工具路由研究，正式实验在 pilot 后固定：

- 一个相同的基础证据包 `E_base`，在所有样本的检查点前提供；
- 一个相同的补充证据包 `E_extra`，只由 `A2` 调用；
- `E_extra` 的组成不由 Monitor 按样本自由选择。

候选专家数量先通过 Stage 0 和 Stage 1 缩减。主实验不以堆叠更多专家换取性能。

## 6. 三种干预动作

### A0：Accept

不增加证据或审计步骤。Actor 沿当前轨迹生成最终标签、中文解释、不确定性和置信度。

### A1：Audit

不调用新取证专家。系统先对已有证据执行结构化审计，再把审计结果交给 Actor：

- 工具是否适用于当前输入；
- 输出方向、阈值和区间是否被正确读取；
- 是否存在缺失、低质量或相互冲突的证据；
- 当前结论是否引用了不存在或越界的证据。

审计中可以包含确定性检查和冻结的中文提示，但不得接触真值。A1 的目标是以较低成本纠正证据读取与信任错误。

### A2：Acquire complementary evidence

调用预先固定的补充证据包 `E_extra`，将其校准输出、能力卡和适用范围加入上下文，再要求 Actor 比较当前假设与最有力替代假设后作答。

A2 的目标是用更高成本弥补基础证据不足。它不允许 Monitor 临时选择任意新工具，从而保持与一般工具路由工作的区别。

三个动作使用相同的最终输出契约：

```text
结论：real 或 fake
证据说明：中文，明确证据与结论的关系
关键不确定性：中文
置信度：0 到 1
```

动作提示、审计规则、专家版本和输出契约在确认性采集前冻结，且不得包含目标标签。

## 7. 同轨迹反事实账本

每个样本只生成一次检查点前缀 `Z_i`，再从相同前缀运行全部动作：

```text
same Z_i
├── A0 -> Y_i(A0), cost_i(A0)
├── A1 -> Y_i(A1), cost_i(A1)
└── A2 -> Y_i(A2), cost_i(A2)
```

令正确性为 `R_i(a) ∈ {0,1}`，相对 `A0` 的正确性收益为：

```text
DeltaR_i(a) = R_i(a) - R_i(A0)
```

令额外成本为：

```text
DeltaC_i(a) = C_i(a) - C_i(A0)
```

给定预先登记的成本权重 `lambda`，动作增量效用为：

```text
DeltaU_i(a; lambda) = DeltaR_i(a) - lambda * DeltaC_i(a)
```

主要结果同时报告原始正确性和成本，不把二者只压缩成单一分数。`lambda` 用于比较不同预算下的策略，不在测试集上调节。

## 8. Monitor

### 8.1 输入限制

Monitor 只能使用动作执行前已经存在的信息：

- 初步标签与置信度；
- 证据摘要和不确定性；
- 专家输出、校准状态、适用范围和缺失；
- 专家之间及专家与 Actor 之间的冲突；
- 可机械检查的引用、阈值和区间一致性；
- 检查点前 token、延迟和调用成本；
- 冻结的模型、提示、工具版本标识。

最终答案、真实标签、动作执行后的文本、补充专家结果和实际动作收益禁止作为输入。

### 8.2 输出

Monitor 预测：

```text
DeltaU_hat_A1(Z), DeltaU_hat_A2(Z)
```

在预算允许时选择预测效用最高且大于 `A0=0` 的动作；否则选择 A0。Monitor 不负责生成最终取证结论。

### 8.3 模型复杂度

依次尝试：

1. 正则化逻辑回归或线性收益模型；
2. 小型树模型；
3. 仅当简单模型在验证集存在明确表达能力不足时，使用小型 MLP 或文本编码器。

不把大型端到端策略模型作为默认方案。模型容量本身不是贡献。

## 9. 分阶段实验与停止门槛

### Stage 0：公开组件复用审计（已完成）

无需 GPU，逐项核对：

- 官方论文、仓库、权重与许可证；
- 安装依赖和接口；
- 训练数据与候选测试集重叠；
- 单张 RTX 4090 的显存与吞吐预估；
- 输出是否支持校准、弃权和能力卡；
- 与完整生成图检测任务的适配程度。

**产出**：[Stage 0 公开组件复用审计](STAGE0_REUSE_AUDIT.md)。推荐冻结现有 Qwen Actor，并在 Stage 1 只筛选 FSD 与 AIDE；用户确认后再下载权重或启动 GPU smoke。

### Stage 1：冻结专家的有效性筛选

在开发数据上单独评估候选专家：

- balanced accuracy、real/fake 分项错误和校准；
- 跨生成器稳定性；
- 专家间错误互补性；
- 失败率、成本和输出可解析性。

只保留能提供独立信息且不会持续单边误导的少量专家。该阶段用于配置环境，不作为论文的主要新方法结果。

### Stage 2：动作可行性 pilot

在未用于旧 pilot 的开发样本上，同前缀采集 A0/A1/A2。开始前登记：

- 样本来源和分组方式；
- 动作提示、模型、专家和校准版本；
- 最小实际差异 `epsilon`；
- 格式合格率、oracle headroom 和独有纠错的通过条件；
- 最大样本数与停止规则。

只有同时满足以下条件才进入 Monitor 训练：

1. 三个动作的输出契约达到预设合格率；
2. A1 或 A2 能纠正部分 A0 错误；
3. 干预也存在误伤，使 A0 具有选择价值；
4. 不同动作存在独有纠错，或其成本—收益明显不同；
5. oracle 相对最佳固定动作的效用差超过预设 `epsilon`。

未通过时先检查前端和动作定义；不得直接训练 Monitor 或在同一批样本上反复调提示后将其当作独立验证。

### Stage 3：Monitor 训练与验证

- 训练集拟合 Monitor；
- 验证集选择特征、阈值、`lambda` 和预算；
- 所有决策冻结后再运行独立测试；
- 测试集只评价一次，不用于选择组件或修改动作。

### Stage 4：独立与 OOD 测试

- 测试集内比较主要策略；
- 按生成器、真实图来源和质量条件分层；
- 增加训练中未出现的生成器和数据源；
- 若更换 Actor，只作为额外泛化实验，不扩大核心结论。

## 10. 数据划分与泄漏控制

- real 与 fake 的类别、分辨率、编码、质量和缩放历史尽可能匹配；
- 同一真实来源及其所有衍生版本属于同一 source group；
- 按 source group 和 generator family 划分，近重复不得跨集合；
- 组件选择与提示调整只使用 discovery/development 数据；
- train、validation、in-distribution test 和 generator-OOD test 分开；
- 公开专家在某数据集上训练过时，该数据集不能被无说明地作为独立测试；
- 旧 T0 和三动作 pilot 只用于发现失败模式，不进入 v2 训练或确认性测试。

正式样本量在 Stage 2 后依据配对不一致率、预设最小效应和计算预算确定。主要正确性比较优先采用配对设计；不以单纯增加同源衍生图代替独立样本。

## 11. 基线

### 11.1 固定动作与简单规则

| 基线 | 定义 |
|---|---|
| Actor/A0 | 从不干预 |
| Fixed A1 | 所有样本执行证据审计 |
| Fixed A2 | 所有样本获取固定补充证据 |
| Best Fixed | 验证集选择的最佳固定动作 |
| Random | 在相同干预率和动作比例下随机选择 |
| Confidence Rule | 仅根据 Actor 置信度决定是否干预 |
| Conflict Rule | 仅根据专家冲突触发预定动作 |
| Invoke All | 每个样本都使用全部可用证据 |

### 11.2 公开方法基线

- AIGI-Holmes、FakeVLM 等可运行专业模型的直接检测结果；
- 与本项目使用相同专家池的 EvoGuard 风格路由基线；若官方实现不可用，需明确标注为透明复现，不冒充原论文结果；
- 适用时报告各单一专家和简单平均/投票融合。

主要比较是 **Monitor 对最佳固定动作的成本匹配增益**。超过较弱的 A0 不足以支持核心主张。

## 12. 评价指标与统计

### 12.1 检测与错误方向

- accuracy、balanced accuracy、macro-F1；
- real specificity 与 fake recall；
- 各生成器和真实图来源的分项结果。

### 12.2 干预收益

- correction rate：A0 错、选中动作对；
- damage rate：A0 对、选中动作错；
- net correction：纠错数减误伤数；
- intervention rate 与动作分布；
- oracle headroom；
- policy regret：oracle 效用减策略效用；
- 预测增量效用的校准误差。

### 12.3 成本

- 新增工具调用数；
- 新增 token、延迟和显存峰值；
- 固定预算下的准确率；
- accuracy–cost 或 utility–cost 曲线。

### 12.4 统计口径

- 以 source group 为独立抽样单位；
- 报告配对差值和按 source group 重采样的置信区间；
- 固定策略与 Monitor 的成对正确性可使用 McNemar 检验；
- 多预算结果以预先指定的主预算为主要终点，其他预算作为曲线和敏感性分析；
- 测试前固定主要指标、最小实际差异和统计方法。

核心成功条件是：

> Monitor 在独立测试集上，以相同干预预算或更低成本优于最佳固定动作；提升同时表现为可解释的纠错增加或误伤减少，并在 source-group 级不确定性分析后仍具有实际意义。

## 13. 消融与失败分析

最小消融集合：

- 去掉 Actor 置信度；
- 去掉专家适用范围和校准信息；
- 去掉证据冲突特征；
- 只保留结构化数值，不使用轨迹文本；
- 不做成本约束；
- A2 改为调用全部专家。

失败分析至少区分：

- 专家本身错误或 OOD；
- Actor 错读正确证据；
- 证据冲突仲裁错误；
- Monitor 选择错误；
- 干预改变了解释但没有改变标签；
- 输出格式或系统执行失败。

## 14. 预期贡献与结论边界

若主要假设成立，本项目的贡献限定为：

1. 建立同一取证轨迹下的多动作反事实干预账本；
2. 提出并验证一个预测干预增量收益与成本的轻量 Monitor；
3. 证明在固定公开前端下，轨迹条件干预能在有限预算内优于最佳固定策略；
4. 给出纠错、误伤、成本和 oracle regret 的可审计评价框架。

本项目不声称：

- 提出新的通用 AIGI 检测器或底层取证特征；
- 首次让 MLLM 调用取证工具；
- 解决开放式工具规划或任意时刻干预；
- 从单一 Actor、单一数据集或少量 pilot 外推到所有取证场景。

## 15. 最近一步

按顺序执行：

1. 用户确认 Stage 0 推荐栈：现有 Qwen Actor + FSD + AIDE；
2. 确认后下载最小权重并完成单张 4090 的 Stage 1 smoke；
3. 在无重叠开发数据上筛选并冻结 `E_base`、`E_extra`、能力卡和校准接口；
4. 冻结 A0/A1/A2 与 Stage 2 停止门槛；
5. Stage 2 证明存在动作选择空间后，才实现和训练 Monitor。

Stage 0 已结束，当前不需要继续开启 GPU。组件栈经用户确认后再进入 Stage 1。
