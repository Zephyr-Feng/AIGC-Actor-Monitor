# Monitor相关工作、代码核验与候选机制

日期：2026-10-09。接续[现行主方案](Actor_Monitor_MVP_Protocol.md)、[机制讨论稿](MONITOR_MECHANISM_DISCUSSION_20261008.md)与[8例试做安排](MONITOR_PILOT_ENTRY_20261009.md)。本轮完成公开论文与源码的定向调研，不改变冻结Actor、8例配置、数据划分或STOP口径；没有模型推理、训练、安装第三方研究依赖或运行第三方代码。候选机制须讨论确认后才能进入新版本实验。

## 判断

建议先完成已确认8例技术检查，再优先考虑两个增量：**逐主张区分“引用一致”与“证据使用合法”，以及定位误用后先要求具体解释修正**。二者可以复用现有结构化字段、工具卡和证据记录，工程范围较小。效果仍需验证，不能给出可信的成功概率。

“独立Monitor”“证据账本”“执行前拦截”“有证据才能STOP”“发现错误后重规划”已有直接相关工作。ECT甚至以“When May an Agent Stop?”为题；这些概念本身不宜作为首次提出的创新。可能有研究价值的是：在真假图像判断中，能否识别**非方向异常信号被转换成真假票**这类证据角色错误，并据此选择更精确、成本更低的干预。此前讨论已经涉及角色检查和修正/补证据分离，本轮把它们细化为可实现、可对照的机制，而非另起一套框架。

## 几处代码细节会改变我们的选择

1. **RefChecker的多参考判定不是“每条参考都检查后保留冲突”。** 其[checker prompt](https://github.com/amazon-science/RefChecker/blob/1df1b25cee792ba2b171302e31ca4f768bd67703/refchecker/checker/checker_prompts.py)先接受任意参考段的蕴含，只有没有参考蕴含时才判断矛盾。若一个工具支持、另一个工具反对，直接套用会丢掉反对方。我们的候选应逐条记录关系，再保留支持与冲突的来源集合。
2. **AgentRx的“跳过语义检查”不能变成PASS。** [checker](https://github.com/microsoft/AgentRx/blob/7a18c79708e7671be15124460f4f7296107c2a55/agentrx/invariants/checker.py)里SKIP_NL路径带skipped标记但verdict写为pass；其用途不能照搬到本项目审核口径。另外代码含生成并执行程序检查的路径，当前MVP只借用预定义CPU约束与违规日志，不引入自动生成程序执行。
3. **EaE的引文筛选失败必须计入覆盖率。** [hierarchical_monitor.py](https://github.com/Aether-AIS/cotrh-blue-team/blob/7dd11d656756cb74215b4adf14b5d25b0f080576/src/cot_red_handed/monitor/hierarchical_monitor.py)有引文提取及无引文样本跳过路径。我们若采用两阶段上下文，应保存筛选失败、漏掉证据和额外调用成本，不能只报告成功抽取子集。少给信息可能减少干扰，也可能隐去反例，需专门核对。
4. **ECT核验的边界明确。** 它检查证据来源、scope、引用及确定性transform结果是否与claim相符。我们已有预算、时间边界、引用有效性等检查，可以逐项对照其结构；但合法引用一个检测分数不等于该分数证明图像真假，不能输出“数学证明STOP正确”。公开源码只下载到本地缓存供阅读，未导入运行或复制进活动代码。

直接复用的优先顺序是：RefChecker的逐主张检查形式 → AgentRx的约束/证据日志形式 → ECT的确定性来源核验。我们可用已有冻结Qwen生成相同结构，无需先接Bedrock/OpenAI后端或增加模型。AgentSpec与EaE主要帮助明确未来干预接口和上下文分离；没有核实许可或论文版本对应关系的源码暂不直接复制。

## 候选一：证据角色与文本一致性分开检查

**解决的具体问题。** Actor可以正确抄出工具数值，却赋予它不允许的含义。例如工具只报告参考分布偏离，Actor却说它“投票fake”。一般文本蕴含器可能混淆“引用数值正确”“工具提供真假方向”“结论得到足够支持”这三件事。

**输入。** Monitor沿用当前调用前可见的原始observation、当时工具卡、Actor结构化提议、预算/可用工具和历史前缀。没有图像GT、silver、当前CALL结果或未来轨迹。它与Actor可使用同样的基础证据，但获得独立上下文及整理后的来源/角色记录；这种组织优势必须在Judge对照中控制，不能宣称有额外事实或模型错误独立。

**检查单位。** 从当前Actor字段中定位可审核主张，记录原JSON指针与原句；只有复合句才做拆分，并保留否定、条件、可能性、说话者、对象和范围。不把“可能存在异常”强化成“存在伪造”，不把工具意见当成真实标签。证据也逐项保留原位置，不拼成一段后一次判定。

**两层结果。** 对每个主张—证据对，分别返回文本关系（支持、冲突、不涉及、无法判断）和用途合法性（允许、违规、无法判断）。用途检查包括：证据在当时是否可见、对象/范围是否一致、工具卡允许它充当什么证据、是否把异常强度转换为真假方向。工具角色明确的部分可由CPU规则核对；中文主张含义、权重或适用性不明确时保留无法判断，不能简单关键词定罪。

| 示意主张，不来自真实案例 | 原始证据/工具能力 | 应检查的具体事项 |
|---|---|---|
| “PROBE报告偏离程度较高” | 只提供参考分布偏离 | 数值与限定是否引用正确；允许描述异常，不自动支持真假方向。 |
| “PROBE因此支持fake” | 同上，工具卡无真假输出能力 | 即便数值一致，也存在角色转换问题；引用原句与能力限制后要求修正。 |
| “两项方向工具均支持fake” | 可见的两项方向判断分别为fake、real | 主张与原始记录冲突；保存两个来源，不用多数投票清除冲突。 |
| “目前证据不足，无法解释冲突” | 有冲突但文字输入无法比较其权重 | 缺口可以成立，不能编造哪一个工具更可靠。补证据动作还要检查相关性、预算和可用性。 |

**预期增量。** 比单一faithfulness标签更容易定位“忠实抄写但用途违规”；逐来源结果能保留混合支持/冲突。通用矩阵及四值状态有先例，本项目候选贡献是图像证据的角色转换审核与后续动作选择。是否减少误放行STOP、会不会错误拒绝合法推断，都尚未知道。

## 候选二：先修正可定位的误用，再决定是否补证据

**解决的具体问题。** 若只是把PROBE说成真假票，继续调用一个检测器并不会自动纠正这句话。Monitor应指出哪里需要改，而不是发一个笼统“证据不足，请继续思考”。

先记录可见文字中的局部依赖，例如“某证据被描述为方向判断 → 综合声称多工具一致 → 用该一致性解释STOP”。只记录Actor明确写出的联系，不称为内部思维链或因果图。首版可限于当前结构已有的证据摘要、综合理由、动作理由，不做全局最小图优化。

示意中文反馈：

> 你在〈原字段指针〉将PROBE的参考偏离写成了fake方向。〈工具卡原文指针〉说明该工具只提供偏离证据。请修正这句及依赖它的“一致支持”描述，重新说明当前真假判断的依据，并保留现有方向工具冲突。此次先修正解释，不据此要求新增工具调用。

反馈在将来在线接入时拦在**Actor提议动作与执行之间**：保存原提议，暂不执行，向同一冻结Actor注入独立的中文约束反馈，由Actor重新生成符合原schema的动作。Monitor不替Actor直接改real/fake结论，也不伪造工具返回。当前离线8例只产出拟反馈，尚未实现这一步。

修正后才分别问：还剩什么实质证据缺口？可用工具卡是否说明某工具能提供相关证据？预算和重复调用规则是否允许？明确时才提议REQUEST_EVIDENCE；仅解释错误时用REVISE_REASONING；违规CALL用BLOCK_CALL；不足以裁决时保留UNASSESSABLE。预算耗尽只能按现有END_LIMITED口径受限结束，不能把原FAIL洗成PASS。这里没有新增“两工具一致即可STOP”的充分性阈值。

**假设与竞争解释。** 具体定位的修正可能减少无效CALL，并提高反馈可执行性；也可能只是让解释更漂亮而不提高判断正确性。Actor重生成本身也可能改进结果。后续比较应包括同预算的一般规范反馈/重生成条件，分别核对解释忠实度、STOP审核和最终判断，不能把一次成功改写当成Monitor有效。

## 候选三：检查变化的主张，但STOP仍完整复核

这是后续节约上下文的可选方案，优先级低于前两项。缓存已核对的证据记录，CALL前审核新增/改变的主张及受影响的依赖；即便没有新工具返回，Actor把先前的“异常”改成“支持fake”也需要重审。STOP做完整复核，避免增量选择漏掉旧缺口。

可实现性来自已有step、结构字段与原始指针，不需要另训模型。风险是同义改写、遗漏引用、置信强度变化难以通过字符串差异判定。先与完整审核比较漏检和token/延迟，未验证前不拿它代替当前完整8例输入；少量开发例也不适合估算总体节省比例。

## 建议如何验证，而不是现在改变实验

1. 先完成当前8例各一次审核及人工逐例语义检查：引用、定位、反馈、修正与补证据区分、无法判断状态。现有结构测试不能替代这一步；同图多条件不是独立样本，silver不是gold。
2. 若语义检查可用，再讨论一个最小比较：同模型、同基础信息的普通规范Judge；逐主张/逐来源检查；再加入角色用途检查。总调用与token预算尽量匹配并报告差异，避免把更多计算量当作方法优势。
3. 后续在线干预需另行确认：配对保存原提议、普通反馈后的提议、具体定位反馈后的提议；冻结工具预算，记录重生成与实际CALL的成本。正式独立标签、来源组划分及样本量要先讨论。74预留组仍不读取。

真正需要看的量包括：错误主张定位及其引文支持、用途违规的误接受/误拒、冲突来源覆盖、误允许/误拒STOP、UNASSESSABLE覆盖、修正/补证据选择是否正确、修正是否传播至相关综合理由，以及额外token/延迟/CALL。报告这些量前需要明确人工标签与分母；当前金标签0，不能给出效能结论。

## 调研方法与可追溯边界

本轮使用本仓库nature-academic-search与hypothesis-generation技能组织定向搜索、来源核验及竞争假设；学术搜索MCP未挂载，实际使用arXiv、ACL/出版方与作者GitHub，通过GitHub连接器读取公开代码。没有将项目私有案例发给文献检索或第三方研究服务。范围为与停止、证据忠实度、约束执行、监测信息访问及取证代理直接相关的工作；不是穷尽检索，没有“未发现即首次”的结论。

论文以此处链接的版本为准；代码以源码审计记录中的commit为准，论文结果不自动适用于当前公开实现。许可描述限于核验到的代码仓库或ECT附带源码，不扩展到数据、模型权重及全部依赖。ECT公开文件及其hash在本地`.cache/monitor_public_sources/ect_2608_23623v1/`供核对，第三方代码未执行。

研究技能的方法来源按其要求注明：[Kassis等，ScientificAgentSkills，2026，arXiv:2609.00065](https://arxiv.org/abs/2609.00065)，DOI [10.48550/arXiv.2609.00065](https://doi.org/10.48550/arXiv.2609.00065)。该来源用于方法组织，不是本项目候选有效性的证据。

当前行动仍为既定8例试做。本文没有批准新的研究条件、专家接入、校准、数据采集或推理；优先候选一、二是在首次技术检查结果可读之后供讨论的增量。
