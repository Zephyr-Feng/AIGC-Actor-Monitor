# Actor-B0-D 审计流程修订

日期：2026-10-08。依据研究者提供的 AGENT_AUDIT_PLAN.md；研究者已明确授权隔离上下文的子 Agent 预审。

原方案要求 80 条轨迹及 827 次 CALL_TOOL 逐条人工标注。本轮改为：80 条轨迹与 827 次调用全量 Agent 预标，随后 80 条轨迹全部人工确认，CALL 按 P0 全量、P1 保留清单及 P2 分层随机抽查进行人工复核。这是风险优先的混合审计，不是 827 次独立人工标注。

冻结 Actor、原轨迹、原人工标签及评估数据保持原版本。Agent 标签写独立文件，reviewer_type 为 agent；人工标签只在研究者逐条查看并明确确认/修改后通过导入入口写回，写回前备份原文件。Agent 提议不会自动变成人工标签。

初审按条件隔离，审计 Agent 不继承聊天历史。每个条件先对调用前信息进行审核并保存标签，再读取本条件的 20 条完整轨迹；配对分析在全部独立预审锁定后进行。GT、准确率、正确性、历史 detector 正确率、诊断类别和原文件名不进入审计 Agent 输入。

审计输入、输出和人审页面使用 blind sample_id；私有 identity_map.json 保存与原 sample_id 的一一映射。这样可以追溯原始步骤，同时避免带生成器后缀的样本 ID 在人审前泄露标签。映射仅由准备/导入程序使用，审计 Agent 和快速人审页面不得读取或显示。

人工 CALL 队列按 record_id 去重并保留全部触发原因。P0 不删减；P1 优先；P2 从剩余高置信 appropriate 记录按 condition × 工具类型 × 调用位置分层、固定随机种子 20261007 抽取。150–250 条仅为工作量目标，超过时保留完整高风险清单并报告原因。

最终包含 GT 的评估只在人工标签完成并锁定后运行。预审结束时 gate 保持 ACTOR_B0_D_INCONCLUSIVE，按用户要求停止，不训练 SFT、不启动 Monitor，不将模型预审称为真实人工审计。
