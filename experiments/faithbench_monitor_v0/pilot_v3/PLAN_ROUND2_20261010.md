# 第二轮：分开来源关系核验与整体审核

冻结首轮条件不改。首轮已观察的前三例中，A/B均漏掉来源归因/假冲突，terminal_0001两组均finding/check不一致；通用提示加来源索引没有显示足够收益。第二轮采用RefChecker式逐声明关系检查，作为新的方法包C，不声称仅由分阶段本身带来的因果效果。

同一8例仍属于反复使用的自适应开发材料。模型、量化、服务与采样保持首轮，C每例两次请求（核验、综合），最多各4096输出、120秒超时。不给模型已有review/首轮输出/gold；核验输入只含Actor声明、此前成功来源与工具卡。核验不做最终真假、停止或建议，降低先决定补工具再合理化指控的风险。

代码从冻结输入定位全部current_evidence声明，保留逐时刻可见来源；每条产生有稳定C编号的observation来源关系和direction角色关系。未知视觉来源标unknown，不能指控图像内容不存在。最新决策action_reason/evidence_gap/unresolved_conflicts另做综合角色核验。核验引用必须来自可见原输入，覆盖所有C编号且不可重复，不修复模型输出。

整体审核使用原v2输入和首轮相同Schema，加未被当作事实的机器核验记录。提醒其可推翻核验但须说明原文依据，先修正已证解释错误，再评判尚存缺口。不能把通用模型局限、未用工具或高强度视为已证明必须补证的缺口；补模型不保证解释视觉物理原因。

指标沿用首轮固定观察点，另记录核验覆盖/引用完整、核验与综合是否冲突、两个阶段总tokens/耗时、失败和回退数量（不自动回退）。两个阶段各自存原响应并复审，若核验失败该case综合不运行，失败计入分母。增加算力与文本是C成本，不把多次调用当同预算公平比较。

不自动将机器关系检查或agent复审写gold，不SFT、不执行Actor动作。首轮输出完整备份/hash核对后才发起C；公开结果只汇总，逐例留private。
