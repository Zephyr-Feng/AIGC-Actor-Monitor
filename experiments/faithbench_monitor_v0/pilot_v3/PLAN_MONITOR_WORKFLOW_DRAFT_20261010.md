# Monitor改进草案：先证据覆盖，再决定SFT

2026-10-10。研究设计草案，尚未改变冻结协议、生成新数据、启动模型或训练。承接[36请求复盘](REPORT_TYPED_SOURCE_FACTORS_20261010.md)和既有v1/v2 SFT复盘。主目标仍是完整Monitor的监察能力，来源核验只是其中一步。

## 为什么现有实验没有形成稳定收益

多数增量诊断围绕同一小批开发材料的提示、格式与来源标签进行；它们帮助定位错误，却没有提供独立效能证据。当前14条SFT监督也很少且相关，不能据此宣称可训练或不可训练。已有mask/目标完整、adapter非零、精度诊断未修复生成退化，因此下一步不能只加epoch、改学习率或再换一条提示。

现有直接生成status/reason/引用的接口允许模型用相邻正确数值替“门牌语义”背书；即使引用逐叶子有效，也不保证当前断言被覆盖。缺列表控制还暴露出理由与状态不一致，阈值控制暴露出忽略来源中明确文本。应分别测量断言聚焦、依据选择、关系和最终决定，避免一个标签掩盖失败位置。

## 建议实现

保持能力卡与实际返回分栏，以及用户已确认的未知/未返回边界。新增候选核验过程：

1. 模型只针对当前片段列出需要来源支持的最小断言，标明实体、属性/关系、数量或限制；上下文用于指代，不替相邻句背书。例：“R1存在”与“R1为门牌附近”必须分开。
2. 为每一项选择实际返回中的最小依据，保留未覆盖的关键内容。允许忠实释义，不能用词面不一致直接判错；不得以路径、坐标、编号证明没有描述的物体语义。
3. 程序负责已确定的结构事实：列表字段存在与否、实际成员和项数、相同来源与时点、引用namespace、明确文本是否漏查、预算和可用动作。每项检查输出可定位的依据；不要从声明中的正确答案构造输入类型或写入门牌/天空等样例专用规则。
4. 模型完成语义关系及中文解释；程序检查理由/状态及断言覆盖的结构一致性。检查失败时拒绝该候选或记录待核验，保留raw；不静默改标签、补引用或用程序结果伪称模型学会了监察。语义覆盖仍需要审阅，程序不能凭规则证明任意自然语言蕴含。

这个分工是待验证的方法改动，可能引入断言拆分错误或额外开销。应同时记录模型自身输出与系统最终结果，分别讨论模型改进和系统改进。对未返回的判定，应审查完整同源返回；只找不到某个叶子或单个关键词不够。新增中间字段及缺字段依据表达需要先确定接口，不能回写历史条件。

## SFT怎么改

先建立一种一致的训练/推理任务和目标格式，全部理由用中文且针对当前片段；禁止把状态/EID字符串当理由。保留逐字段loss诊断，但验收以自由生成的完整解释、引用、关系为准。已有8B基座和隔离LoRA代码可以复用，Actor和原基座保持只读；不因27B更大就直接把其错误输出作教师gold。

建议在已批准开发来源内设计经审阅的成对控制：保留编号但改变属性、保留阈值但改变邻近分数、列表存在与删列表、工具能力与实际返回区别。控制只能用于明确的辨别目的；这份草案尚未生成或标注它们。训练材料要覆盖正支持、未返回与未知，理由明确指出决定性内容；不能批量复制同义模板制造样本数量。

先验证少量监督样例在实际训练/生成路径上能学到完整理由和依据，再检查不参与训练的控制家族是否保持正例、不漏直接证据、不把未知当错误。失败则回到具体断言/依据/生成字段排查，不追加优化步数。样本数、步数、dtype、adapter目标层及用卡时间需要在材料和检查确定后单独冻结；现在不先拍预算。

已经反复看过的开发片段可以做回归，不能充当未见测试。即使把部分控制留出训练，也只是开发集内的控制家族验证，不是独立来源组泛化。74预留组、GT和身份映射仍不读。

## 回到完整Monitor的验收

在局部核验能稳定覆盖断言后，用已批准的完整轨迹检查冲突有没有被正确识别、限制有没有被遗漏、预算/可用动作下停止是否合理，以及干预理由是否只依赖已发生证据。沿用既有最终聚合草案作为候选，不执行Actor动作。研究结论必须区分接口通过、局部来源核验、完整监察及独立效果四个层次。

下一项具体工作建议是CPU核验流程原型和监督样例审阅；新接口/数据控制/训练条件确定后再进行有界对照。依AGENTS第1条，存在影响标注/实验方向的未决选择时，先带这份具体方案与证据确认，不能将草案视为已批准运行协议。
