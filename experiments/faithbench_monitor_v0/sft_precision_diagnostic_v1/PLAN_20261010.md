# 已有 Monitor adapter 的精度路径诊断（不优化）

2026-10-10。v2复盘和32输出首审／复审完成后设计。本轮不产生新训练候选，不依据结果自动加步数、调学习率或扩大来源。

## 问题与相互区分的预期

训练BF16 autocast，原评估无autocast；PEFT将非量化参数／adapter转FP32。若这一差异是主要原因，**同一已保存adapter**在BF16 autocast推理应恢复理由，而原路径复现旧错误；字段条件损失／reason首token概率也应显著不同。若两路径均退化，不能靠切autocast解决，转向目标条件学习与自由生成分歧／小样本更新干扰。若重载原路径不复现，先排查序列缓存、加载状态，不比较后续能力。

## 冻结范围

- 基座关闭adapter、已保存v1、已保存v2，均 `eval`、无梯度／无optimizer，不合并、不覆盖adapter。
- 各状态无autocast／BF16 autocast两个路径；保持原NF4 double quant、BF16 compute、SDPA、greedy、max_new_tokens384。
- 对**相同v2的14个完整目标**计算teacher-forced总NLL以及reason、status/relation、refs、格式各段NLL、reason首token top候选；共84个forward。不能跨不同长度目标比较总loss来声称能力改善。
- 自由生成仅四个已有请求：R13_terminal_0005_A006（R1支持）、A007（门牌未返回），R13_terminal_0001_A009（训练阈值支持）、R14_terminal_0002_A006（训练行外9/9支持）。4×3×2=24，不重跑65或最终聚合。
- 原路径的12输出与旧base/v1/v2 raw逐字比较；另外12只用于精度敏感性。所有输出保留，分别审核结构、解释、引用与关系；不重写旧解析器／指标。
- 在同一前向记录embedding、首个语言q_proj的基础层／LoRA A、lm_head输入输出dtype，确认实际路径，不能只看配置。
- 不读取新来源、74组、GT、身份映射；不访问图像、不执行反馈，Actor/基座仍只读。输出新目录，单实例锁和进程/GPU检查防重复；每60秒诊断日志、进程及资源。

## 执行门槛与停止条件

输入manifest／adapterhash、四请求选择和目标逐条核验；CPU tokenizer与字符offset重建完全相同，不截断。冻结清单前后相等。预计用4090约4–8分钟，仅已有模型加载／推理。原路径不复现、OOM、非有限loss、无日志推进超过预期时暂停受影响步骤，查明证据。无研究因果或独立准确率结论；本方案只定位实施差异。
