# 旧Monitor与Actor反馈处理层方案

状态：用户要求制定方案；本文不构成实现、模型调用、训练或新数据分配的执行记录。目标是先验证反馈处理能否减少误改，并改善Actor最终回答。第一版只做一次局部反馈修订，不扩展为多轮自主取证。

## 1. 固定条件与已有实现

- Monitor使用00373候选，00453不接入。Actor模型、权重及已有证据固定；00373仍是开发候选，不视为可靠裁判。
- 使用已有中文契约：`结论/问题/保留/说明`；问题项含`状态/回答原文/证据ID/理由/建议`。不要求旧模型突然生成未训练的新字段。
- `assemble_feedback.py::assemble`已经校验结构、证据ID和原句存在性，返回定位候选及原始来源；它只标记引用有效，明确返回`semantic_verified=False`。多处出现的原句目前只是标记不唯一，新处理层须据此阻止自动应用。
- `src/actor_monitor/checkpoint.py::build_branch_messages`已有从同一前缀建立Actor分支的机制。原A0/A1/A2提示和历史结果保持原样，新分支单独实现和记录。
- 本轮简化FAVA输出只有原句/替换文本，没有理由与证据绑定；不能自动补造依据后当成中文Monitor反馈。
- 参考本地[研究协议](../../../docs/Actor_Monitor_MVP_Protocol.md)、[混合训练结果](FAVA_MIXED_RESULT_20261019.md)及当前实现。文本数据上的现象不能直接证明图像取证闭环有效。

## 2. 第一版处理流程

`Actor初稿及已有证据 → 00373候选反馈 → 程序校验与分流 → Actor逐条复核并提出局部修改 → 程序验收 → 最终稿或原稿+未决记录`

### 2.1 接收与结构检查

保存初稿、原始反馈和证据快照，调用现有assemble。结构非法、未知/重复证据ID、找不到原句时，整份反馈拒绝执行，保留原文并标记处理失败；失败不能计为Monitor判定通过。格式正确但某项定位不唯一时，该项进入未决，不猜字符位置。

只将程序从输入证据中取得的原文送给Actor，不让Monitor改写证据。证据和待核回答均作为待审数据包装，不能覆盖Actor指令；不使用正文里的命令触发工具或程序操作。

### 2.2 逐项分流

| 情况 | 动作 |
|---|---|
| 仅格式通过、Monitor声称明确错误 | 标记为待复核候选，附原句、完整相关证据、理由及建议，不能直接执行 |
| 证据不足、证据冲突或定位不唯一 | 保留原文并记录未决，不计为事实审核通过 |
| 可确定仅为空白调整、替换前后相同 | 不触发事实修订，记录过滤原因 |
| 一般措辞变化或复杂自然语言关系 | 规则无法可靠分类时交Actor核对，不能凭词表断言无害或正确 |
| pass但发现明确可比较的字段冲突 | 阻止静默放行，生成可追溯的复核项；不自动改写结论 |

结构化检查只覆盖已有可靠的“主张—字段”对应：同一实体、属性、时间范围、单位明确时，比较布尔值、数字等。缺失/null不等于false；不靠否定词搜索猜语义，不把数值接近当支持。无法建立对应就记录无法自动核实。

图像取证中，工具异常分数不自动映射real/fake，无方向性的观察不能因值大而当作伪造证据。这类语义约束由证据卡定义和Actor复核共同落实，不能从文本试验中的false规则直接泛化。

### 2.3 Actor复核与局部修订

第一版一次调用，批量处理本例候选项。每项输出：问题编号、接受/拒绝/未决、中文依据；接受项另给证据ID、原句和替换文本。要求依据原始证据，明确允许拒绝Monitor建议；不采纳纯润色或缺乏支持的删除。

Actor返回局部修改，不返回自由重写的全文；程序负责拼接。原句必须属于获准复核区域，证据ID须有效，修改之间不得重叠。修订不得自行扩大到其他段落、整体真假标签或置信度字段。第一版研究解释的事实性，标签更新及多轮补证据另设实验条件。

明确删除仍可作为候选，因为原文可能含无依据断言；必须给出具体被证据否定或不支持的内容及依据。规则无法认证这种判断，不能将“有删除理由”当成删除合理。

对于证据不足，第一版不自动调用新工具。保留带未决标记的草稿和所缺证据类型，避免以通过状态发布。未来在线取证可由Actor在明确预算内选择工具，Monitor不代选具体工具。

### 2.4 修改验收与回退

只接受合法、定位唯一、范围内且互不重叠的局部修改，从后往前应用。未涉及区域必须与原稿逐字相同。重复项先去重；重叠或相互依赖而无法拆分的项整体回退。Actor输出无法解析时，本例全部回退。

对已明确映射的字段重新执行结构化冲突检查；若修订仍违反该约束，则回退相关修改。每项记录提出、接纳、拒绝、回退原因，保留原稿和候选稿。

这些检查保证引用、边界和可回退性，不保证语义正确。第一版不再增加一个同模型“自判正确”的调用，以免将自洽误当真值；内容质量由预定评估检验。

## 3. 最小实现范围

以下均为拟新增文件，不表示已实现：

| 位置 | 职责 |
|---|---|
| 当前目录`feedback_control.py` | 复用assemble，校验、分流、构造含原始证据的修订请求，验收局部修改；不发模型请求 |
| 当前目录`replay_feedback_control.py` | 用已保存输入/输出做CPU回放，输出逐项处理记录及汇总 |
| 当前目录`test_feedback_control.py` | 少量合成夹具覆盖核心边界与回退，避免读取保留研究数据 |

优先复用现有引用定位与证据组装函数，不复制验证器，不改变旧评分口径。运行任何既有入口前检查其调用链，禁止直接、替代或间接哈希核验。无需新依赖。

## 4. CPU阶段验收

优先复用已有32条中文回归输出及本轮已记录失败案例；这只是固定资料回放，不分配新训练/评估集。7条FAVA无错案例只能作为错误修订夹具或人工复核材料，不伪装成带证据理由的原生中文反馈。作者标签和助手意见都不称人审gold。

至少覆盖以下功能边界：

1. E003不存在：反馈拒绝，原稿不变，状态不是pass。
2. 重复空格/同句多次出现：禁止猜测定位和应用。
3. null与false区分；未建立主张映射时不宣称已核实。
4. 正确映射下的布尔、数字冲突，以及单位/实体/时间范围不一致时拒绝直接比较。
5. Actor拒绝建议或提出未决：保留原文和未决原因。
6. 范围外修改、重叠修改、非法输出：按约定回退；互不重叠的有效修改正常拼接。
7. 有据句误删、wrote→stars等案例：明确它们属于语义验收风险，不能要求通用字符串规则假装识别所有此类错误。若模拟Actor接受且规则未拦住，记录残余风险，不能算防误改成功。

验收要求：以上可机械判断的边界全部通过；旧assemble测试不退化；逐项日志可追溯；回放计数守恒，拒绝/未决不混入成功纠错。CPU通过只允许进入有界闭环试验，不宣称有效性通过。

## 5. 后续真实闭环评估草案

### 比较设计

以同一来源、同一Actor初稿和同一证据快照配对比较三个条件：

- A：原稿保留，无反馈修订，作为伤害与收益参照。
- B：旧Monitor反馈经基本结构校验后直接交Actor复核，使用相同的局部输出接口。
- C：增加本方案的反馈分流和修订验收，其他条件与B相同。

B/C复用同一次Monitor输出，Actor版本、解码设置、证据和单轮输出上限一致；共同遵守基本接口安全检查，不为制造对照执行非法引用。B也记录程序能够解析但未经C额外约束接受的候选结果。C不触发调用时保留原稿并如实计零次调用。比较B/C回答处理层的增益，A/C回答整个反馈流程的净效益。

没有另设无Monitor的泛化自省组，因此不能把A/C差异全部归因于Monitor知识；B/C仍是整套处理策略比较，不能分离其中单个规则的因果作用。

### 数据、规模与调用上限

先盘点已授权、已有缓存的目标领域开发来源，不读取FULL20或GT/44保留集。自然文本回放仅验证工程链路；图像Actor闭环须使用对应图像、合法取证证据与原始轨迹，不拿文本纠错成功代替图像任务成功。

建议开发试验以64个独立来源组为上限目标，每组一个主案例，尽量覆盖原始有错和原始无错两类；这是工程诊断规模，不是统计功效保证。若现有缓存不足，先报告缺口，不复制变体凑独立样本，不自行新增生成或分配。先检查初稿正确性及来源关联，再冻结实际清单与分层；同源变体按组统计。

在64组均有可复用初稿的前提下，最多64次Monitor和128次Actor修订，共192次新增生成；若合法Monitor缓存可复用则减少调用。无自动重试；失败保留并计入覆盖。缺少初稿时不默认为可再生成64条，需重列范围与预算。先明确具体Actor/API或本地运行方式，再给出金额、GPU时间、输入输出token及绝对截止；本次8小时旧预算不结转。

### 评价与停止条件

盲化展示条件标识后审阅证据与修改，分别记录原有错误修复、新增错误、正确有据内容损失、残余错误和未决项。首要报告相对原稿的新增错误/有据内容损失，以及每来源组修复数减新增错误数；同时列出原稿有错/无错分层、B/C配对转变和实际调用成本，不以一个净分掩盖伤害。

来源标签匹配、格式通过率仅作辅助指标。若只有助手复核，明确为开发初评，不写独立人审准确率。来源组为分析单位，多个断言或多份变体不当作独立重复；小样本展示计数与不确定性，不凭几个案例宣布统计优势。

出现已确认的严重有据内容误删、证据关系颠倒或伪造引用，暂停后续调用并检查原因；结构/回退失效立即停止。失败与已完成输出保留，不通过临时改提示后续跑来混合条件。预算到限停止；缺失结果和提前停止会限制效益估计，不能只报告成功样本。开发门槛为机械检查通过、未观察到严重新增错误、纠错净收益为正且无错组未退化；即使达标也仅支持进一步独立验证。
